# SlateSync 本地场记单识别优化方案

日期：2026-10-27。状态：阶段性实施中，真实数据校准与后续实验待执行。适用范围：当前 Swift 原生识别链路。

实际落地内容、验证与剩余项见 [实施记录](recognition-optimization-progress.md)，不能将本方案中的拟定目标视为已经达成。

2026-10-28 新增[场记单结构识别优化方案](ocr-structure-optimization-plan.md)，细化动态裁图、行列与合并格证据、无损图像实验、定向区域复核四项工作；2026-10-29 修订为测试收敛版。本专项按定向回归、小样本筛选和最终候选验收执行，具体样本规模、重复轮次及本地检查频率以专项方案第九节为准，仓库必需检查保留。专项代码已写入且默认关闭，获准的离线编译与回归已通过，真实效果验收待执行；详见[实现状态](ocr-structure-implementation-status.md)。原图提取、方向校正与跨阶段流水仍按本总方案推进。

本方案先解决同一版式不断生成新模板的问题，再改善字段准确率、重复任务速度和人工校对效率。目标是让不同填写内容、扫描尺寸和识别模式下的同类场记单稳定复用模板，并让不确定内容有证据、有回退、可校对。

实施顺序确定为：隔离评测与诊断 → 模板归属与历史兼容 → OCR 复用与图像质量 → 表格和字段识别 → 自适应复核 → 专用模型实验。首个交付应完成前两项，不以更换 OCR 模型作为前置条件。

### 人工 CSV 真值接入

CSV 按列名读取，不能依赖不同导出文件的列位置。`Reel Name` 用作候选素材键，`Scene`／`Shot`／`Take` 对应场／镜／次，`Comments` 中 `_OK`／`_KP`／`_NG` 采用现有业务状态映射；保留字母后缀及 `1-1` 等复合次号，不做数值化截断。

初步映射覆盖 36 个日期组，全部 45 份 PDF 都找到同日期 CSV；`260820.csv` 暂无同日期 PDF。日期相同只表示候选关联，不能证明 CSV 全部素材都在这些纸张上；场记单与日报分开处理，确认原稿覆盖后才统计漏行。重复导出中相同键、相同关键字段仅计一次并保留来源；9 组冲突已按用户确认从本轮评分排除，保留全部原始版本。4,147 组一致记录中，4,072 组存在同日期 PDF；另外 75 组属于缺少 PDF 的 260820，单独保留不计漏识别。空字段和非标准键记录先保留待分类，不直接视为错误、负例或零值。

纯图片识别评测不得向模型提供目标 CSV 的场／镜／次／状态答案，也不能把评分侧素材键偷偷作为识别输入。若评估生产 CSV 辅助模式，应单独列为辅助识别实验。字段真值不能替代人工模板家族标签。日期／物理原稿分组冻结后再分开发和留出集合。

只读盘点与候选真值位于 `${SLATESYNC_VALIDATION_ROOT}/recognition-ground-truth`，记录源文件 SHA256 与 CSV 记录序号；目前还没有执行真实字段准确率测试。

### PDF 提图与自动调正的实现约束

开发评测已用 pypdf 成功提取一页原图并目视检查。原生产品优先在现有 PDFKit／Core Graphics 路径内实现，工具提图成功不代表 App 已集成。仅在能证明单一主图及其变换覆盖所需内容、没有不可忽略的叠加文字／矢量标注／遮罩时直接提图；其他页面保留完整渲染回退。图片像素比页面尺寸大，属于保留原图细节的机会，不直接等同于识别更准或更快。

方向处理依次考虑 PDF 页旋转、图片绘制矩阵及镜像，再通过低分辨率表头／文字方向判断 0／90／180／270 度；仅在方向不确定时比较多个候选，不对每页默认做四次完整 OCR。轻微倾斜由长表格线与文本基线估计；透视校正只在可靠边界存在时启用。置信不足保留原图或完整页回退，变换带安全边距并记录内部坐标映射。验收加入已知角度的旋转样本、倒置、低清晰度、矢量叠加与多图页面，避免仅验证处理后的图片“看起来正”。

### 短期项目与自适应复核

任务数不作为硬性自动学习开关：用户可能重用已有模板，也可能只有一个多页任务。默认保证无需学习即可完成首个任务；正式模板仅在主动确认时创建，候选管理为可选操作。暂不追加模板修订、稳健聚合或拆分系统。已实现的候选和合并能力保留，后续可减少不必要提示与后台写入，但不批量删除用户模板。

自适应策略先以影子结果对照严格模式：低风险要求关键字段完整、素材身份无冲突且独立覆盖检查充分；中风险仅重看相关区域并保留全页上下文；表格覆盖不明、整行疑似遗漏或多机位冲突则执行全页查漏／裁决。不能仅以 OCR 或模型自报分数跳过检查。复核设置总调用和重试预算，仍无法确定时沿用现有待确认结果。顺序触发复核可能使高风险页变慢，必须同时比较请求量、低风险耗时和高风险 p95，验收通过后才改变运行策略。

## 一 目标与范围

### 产品目标

1. 同一种结构的多个样本归属同一模板，不因日期、卷号、填写行数、扫描尺寸、PDF 页数或标准／高精度模式变化而自动新增正式模板。
2. 不同字段顺序、不同摄影机区块等真实结构差异能够被区分；无法判定时保留不确定状态。
3. 降低漏素材、错卷、场镜次错列和状态符号误读，保持未知字段留空及复核标记。
4. 减少重复解码、OCR、模型加载和无必要复核，分别改善首次处理、重复处理、批量吞吐和首个结果延迟。
5. 评测与正式项目隔离，形成可重放的输入、版本、输出、诊断和人工真值。

### 范围边界

本地 OCR 是端到端识别的一部分。当前结构化识别还调用配置的 Provider；是否完全离线取决于该服务的部署方式。纯本地完整识别列为后期路线，不能将 OCR 本地化等同于整条流程离线。

保持 macOS 15 兼容路径、项目隔离、取消与关闭排空、字段冲突保护、Resolve CSV 字节与回填约束。首轮不改变 20 页输入上限、不引入无限制图块数量、不自动修改素材源文件、不批量清理用户模板。

所有性能百分比均属于后文的拟定验收目标，需要在相同硬件、数据和配置的基线上验证。现有功能测试通过不等于真实手写准确率达标。

## 三 模板与样本的职责

| 概念 | 保存什么 | 身份与更新规则 |
| --- | --- | --- |
| 源文件与页面 | 原始内容摘要、页码、来源及必要的渲染信息 | 精确摘要识别相同输入；文件名只用于显示 |
| 页面观察 | 一次实际检测到的文字、结构、区域、质量和引擎版本 | 可多次运行；观察不自动等于正式模板 |
| 模板家族 | 稳定的字段布局、摄影机区块和继承规则 | 使用稳定 ID，不随每次观察指纹改变 |
| 模板修订 | 同一家族内经确认的结构参数改进 | 保存版本，旧任务绑定当时版本 |
| 识别结果 | 当前页面实际的卷号、素材键、场镜次和状态 | 由当前证据产生，不从模板历史内容填入 |
| 字段证据 | 原值、候选、来源区域、修正理由、确认状态 | 与值共同流转，区分识别、规则推断及人工确认 |
| 评测样本 | 原稿、人工真值、真实模板标签、数据划分 | 独立于 App 自动分配的模板 ID |

“模板家族”不是把相似模板无限合并。字段对应关系和解析语义相同，仅发生缩放、拍摄形变或笔迹变化，属于同一家族；字段顺序、摄影机区块组织或继承语义发生实质变化，应分为不同家族。行数伸缩、标题变化和不同页角色不能单独决定新家族。

同一个 PDF 可以包含多个模板家族或页角色，应按页归属。整份文件只是页面集合，不能把文件的页数组合作为单个模板身份。

现有 Scenario Profile 继续承担兼容读取和用户选择入口。新概念首先体现为匹配描述与关联契约，不要求首轮将所有实体拆成独立服务或表。

## 四 模板稳定识别

### 结构特征提取

第一版新匹配器仅从全页证据提取身份特征，消除多视图混用；局部 OCR 仍可参与内容识别。后续局部结构参与前，必须具备原页坐标映射。

结构描述至少包含：规范表头及其左右顺序、相对列区域、摄影机区块及重复关系、表格区域比例、可靠的线段或单元格边界、页角色、证据质量和特征提取版本。

提取规则如下：

1. 按纸张或表格边框统一坐标，进行必要的旋转／透视校正；不要以随填写内容变化的黑色像素包围盒作为唯一参考框。
2. 将场次／场景／Scene、卷号／卡号／Reel 等明确表头映射为领域字段；处理合并文字块时保留分词与位置证据。
3. 避免直接子串匹配导致“次”命中“场次”。表头解释需要字段上下文、完整词及相邻列约束。
4. 日期、卷号值、场镜次值、拍摄内容、备注、OCR 检出块数、精确像素尺寸及文件页数不作为身份特征。纸张长宽比只能作为辅助信息。
5. 通过已识别字段区域和语义角色排除动态内容，不用一条“所有数字都删除”的规则破坏模板版本名或真实结构信息。
6. 摄影机分组统一识别 A机、A 机、ACAM 等受支持别名；保留“未观测到”与“确认不存在”的区别。
7. 行列比较关注相对位置、顺序、边界和重复拓扑。已填写行数不作为结构列数／行数的替代。

只修改哈希算法不能解决此问题。需要先改变进入哈希和相似度计算的特征；结构摘要用于索引与去重辅助，最终归属仍依据可解释的结构比较。

### 候选检索与比较

先按字段集合、顺序和机位区块检索候选，再对候选做几何对齐、边界与拓扑比较，避免每次识别加载全部模板 JSON 逐一计算。候选索引按项目与模板修订失效，首轮可采用内存索引，不引入外部向量库。

评分必须返回分项证据：哪些字段一致、哪些结构冲突、哪些项目缺失、有效证据覆盖率，以及最佳家族和次佳家族的差距。多个修订或旧模板别名先归并为家族，再比较第一、第二名，避免同一家族自相竞争。

缺失项不得直接计为满分。只对已观测特征计算相似度，同时设置最低证据覆盖要求；两个样本都缺少机位标签，不构成机位布局一致的证据。字段顺序或区块结构的明确冲突可以否决自动复用，不能仅靠其他分项补分。

阈值、差值和几何容差由开发集校准后冻结，并通过独立测试集验收。禁止只降低现有 0.85 门槛来减少新模板数量。

### 匹配结果与保存策略

| 结果 | 条件 | 用户任务行为 | 模板写入行为 |
| --- | --- | --- | --- |
| 已匹配 | 结构一致、证据充分、可区分其他家族 | 应用对应模板并保留匹配依据 | 关联观察，不新增正式模板 |
| 候选接近 | 两个不同家族均有支持证据，难以区分 | 使用通用识别，允许选择已有模板 | 暂存观察与候选，不创建正式模板 |
| 证据不足 | 模糊、裁缺、表头缺失或结构检测失败 | 使用通用识别并说明原因 | 不新增正式模板 |
| 新版式候选 | 结构证据充分，与已有家族有明确差异 | 使用当前结构辅助识别 | 保存候选；经用户确认或后续明确的晋升规则转为正式模板 |
| 用户指定 | 用户选择了已有模板 | 优先采用；明显冲突需提示并保留通用回退 | 不由一次指定结果自动改写模板结构 |

候选相近和证据不足都不阻止完成识别。新候选按结构相似性聚合，设置项目级容量与保留期限，避免把“正式模板膨胀”变成“候选列表膨胀”。首版采用用户确认晋升，批量自动晋升放在证据充分后的扩展阶段。

新建候选的匹配分数应为空或独立表示“无已有匹配”，不得沿用 score=1 表示成功。界面和诊断必须区分“与已有模板匹配的分数”和“新结构证据的质量”。

### 样本积累与模板更新

结构观察先暂存；成功任务满足提交策略或用户明确确认后，再写正式关联。失败或取消运行不得新增正式模板或推进模板修订。重试使用稳定运行与样本标识，避免重复计数。

区分运行次数、观察次数与独立样本数。精确相同输入重复识别不增加独立样本数；不同扫描是否属于同一物理样本由明确关联决定，不用感知哈希自动认定内容相同。

复用记录不立即覆盖原模板。只有已确认归属、结构质量合格的样本参与更新，按可靠锚点的稳健统计改进列区域；偏差大或明显分成两组时提出拆分候选。保留上一修订及变更依据，人工确认的结构不被单次低质量 OCR 冲掉。

模板结构与任务输出配置分开处理。现有 Profile 中的 Resolve 配置、自定义提示与人工说明不得在家族合并时按相似度静默覆盖；采用项目／任务明确配置，并展示冲突。

## 五 历史兼容与重复模板治理

SM-05／SM-06 中受本方案影响的实现冻结已按 [识别实现演进决定](recognition-contract-evolution.md)进行范围明确的替代。新行为使用独立回归验证，历史夹具和批准记录保持原样。

采用以下演进顺序：

1. 保留旧 Profile 解码、指纹计算与历史回放，将新结构特征标记为独立的提取／匹配版本。存储 schema 版本与特征算法版本分别管理。
2. 先做只读影子匹配：新算法输出候选与差异报告，不改正式归属、不触发旧算法的自动建模副作用。
3. 新写入前完成存储 ADR，明确新增匹配描述、家族关联、别名和修订如何持久化，以及项目包如何携带。优先评估附加数据的兼容方案，但不能假设“加表”就天然兼容旧客户端和包校验器。
4. 迁移前使用现有项目导出／快照边界备份；所有写入经 ProjectRuntime 租约和事务，不由匹配服务绕过持久化所有者直接打开项目数据库。
5. 生成重复模板合并预览：列出源 ID、目标家族、支持证据、涉及任务数量、说明与输出配置冲突。首版不自动执行批量合并。
6. 确认合并后保留旧 ID 到新家族的别名映射，旧任务、观察和显式 scenarioId 仍可解析；历史结果及其当时模板版本保持可追溯，不删除原始观察。
7. 合并及撤销都作为事务化操作记录映射前后状态；失败不能出现计数更新了但观察丢失的部分提交。重开、取消、导入导出和冲突案例纳入回归。
8. 回退必须区分“关闭新匹配算法”和“运行旧版本客户端”。前者可保留新记录并切到兼容通用路径；后者若无法无损读取新格式，应明确要求使用迁移前备份，不能让旧程序静默忽略重要数据。

新增家族沿用项目隔离，不默认跨项目共享。旧模板没有足够原始结构证据时保持未分类状态，不能根据文件名或现有哈希强行归并。

## 六 独立评测体系

### 数据集与标注

首批建议准备 150–300 页、覆盖实际最常用的至少 5 类版式；数量是启动规模，不构成高准确率的统计证明。如果当前只有少数真实模板，先保证每类覆盖充分，再扩大类型。

样本应覆盖电子 PDF、可靠／不可靠文字层、扫描件、手机照片、不同分辨率、轻微旋转／透视、浅色笔迹、涂改、合并格、多摄影机、换卷、范围条号、跨页与混合模板文件。补充少量明确不可读样本，检验系统能否正确保留未知。

每个样本的标注清单至少包含：sampleID、sourceGroupID、相对文件路径、文件摘要、页码、人工 templateFamilyLabel、页角色、采集方式、书写者匿名分组、质量标签、真实记录、关键字段来源区域、不可读标记、标注版本和数据划分。

真实模板标签由人工定义，不使用 App 预测 ID 回填；模板分组、关键素材键及争议字段需要复核。真实业务内容保存在受控的本地数据集，仓库与公共 CI 使用获准的脱敏样本或确定性合成夹具；不为采集评测集自动上传用户原稿。

### 防止评测污染

评测入口复用生产实现，但注入只读模板快照与独立输出目录，不调用正式 applyScenarioMatch，不更新 lastUsedAt、sampleCount、模板修订或正式任务。评测前后核对逻辑状态与写入审计。

分开运行三类评测：

| 类型 | 模板状态 | 验证内容 |
| --- | --- | --- |
| 已知模板泛化 | 固定训练样本产生的模板快照 | 不同填写内容、书写者、扫描方式能否正确复用 |
| 未知模板识别 | 留出整个模板家族 | 能否拒绝误归属并提出合理候选 |
| 持续学习模拟 | 独立临时库，按明确顺序推进 | 样本累积、候选晋升、合并与修订是否稳定 |

同一物理页的多次扫描与增强图归入同一 sourceGroupID，不能跨开发／测试集合。已知模板评测可共享家族，但按实际页面、书写者或批次留出；未知模板评测按整个家族留出。阈值只在开发集校准，测试标签不能参与在线匹配。

固定快照评测应对输入顺序不敏感。持续学习评测单独报告顺序效应，不将两类结果混合。真实 Provider 评测与离线回放分开，合成响应验证流程，真实响应才用于模型准确率结论。

### 指标定义

| 指标 | 定义与报告方式 |
| --- | --- |
| 自动归属覆盖率 | 自动归入已有模板的已知模板样本数／已知模板样本数 |
| 自动归属正确率 | 自动归属正确样本数／自动归属样本数；与覆盖率同时报告 |
| 家族误合并率 | 自动关联中跨真实家族的错误比例，并报告具体家族对 |
| 家族碎片数 | 每个真实家族对应的正式模板家族数量；无归属样本另列，不能藏入统计 |
| 未知模板误接纳率 | 未知家族被归入已有家族的样本比例 |
| 素材记录 precision／recall | 按真实素材键及相应页面证据匹配，分别衡量虚增与漏行；重复记录单列 |
| 关键字段 exact match | 卷号、视频码、场、镜、次、状态逐字段及整条全部正确率；允许的规范化由标注规则固定 |
| 自动通过错误率 | 被自动接受的关键字段中实际错误的比例，和自动通过覆盖率共同报告 |
| 人工校对成本 | 每 100 条记录修改字段数、确认次数与实际校对时间 |
| 性能 | 冷／热启动、准备、排队、OCR、结构、Provider 各阶段耗时及端到端 p50／p95、首个结果延迟、峰值内存 |

不可读真值独立统计：返回未知是合理结果，猜测成非空错误值需要计入错误。普通清晰样本上的大量返回空值不能提高产品验收成绩。

真实样本报告同时列出样本数、分层结果和统计区间。样本不足以支持 99.9% 等结论时，只报告观察值，不将零错误外推为普遍零风险。

## 七 图像与结构识别

### 输入与质量分流

优先判断输入是否有可用的 PDF 文字层。文字层需要检查字符有效性、位置与图像的一致性及区域覆盖；仅表头有文字时，只复用表头，手写内容仍进行 OCR。PDFKit 提供文字选择、逐行拆分及范围坐标，可支撑该路径。[Apple PDFKit](https://developer.apple.com/documentation/pdfkit/pdfselection/attributedstring)

图像质量检查输出失焦、反光、倾斜、透视、字高不足、裁缺等可解释信号。清晰扫描件不必执行昂贵去畸变；存在问题的区域才尝试相应处理。无法恢复的内容提示重新提供更清晰来源，保留通用识别与人工补录通道。

### 图像用途分离

保留不可变的源文件引用或受限原始字节，按页解码；不要为追求质量把全部页面最大位图常驻内存。本地 OCR 输入、预览图片、Provider 传输图片使用各自的配置与预算。

本地 OCR 不受 Provider 的 80 MiB 等请求预算压缩结果反向影响。后续局部高清图从原始图片或 PDF 对应区域生成，不能用低清缩略图插值放大冒充新增细节。

传输预算按实际发出的单页／阶段完整请求计算，包含图片编码、提示词、OCR 证据和其他上下文，不用整份文档的累计大小迫使所有页面统一降质。每个候选 Provider 的有效限制在发送前校验，压缩不得原地改写保留的 OCR 输入。

标准模式按需准备全页；只有需要复核的区域才生成局部图。初期仍保留现有公共 1／3 视图契约，内部可按需选择最多两张局部图。若以后需要更多图块，另行定义批次、上限、恢复键和协议版本，不直接删除现有校验。

### 坐标与结构

每个局部图保存来源页、来源矩形、旋转／透视变换与图块身份。带重复表头的拼接图属于分段映射，不能用单个缩放矩阵把整幅拼接图当成原图。无法准确回映的证据不参与跨视图几何合并。

建立“表格 → 行列／合并格 → 摄影机区块 → 单元格”的中间结构。文字候选按结构归位，场次／镜号继承只在有证据的合并范围内传播；跨页继承沿用明确规则，不按素材编号推测。

固定 62% 宽度与 22% 表头裁切保留为兼容回退。已验证模板先定位表头、核心列及右侧机位，再按完整行或格边界裁图，并保留邻接上下文。未知模板以全页识别和检测到的结构为基础，不能从一个弱匹配模板强行裁掉信息。

Apple RecognizeDocumentsRequest 可返回表格及单元格行列跨度，适合作为支持系统上的结构识别候选；中文手写和复杂场记布局须单独评测，低版本继续原路径。[Apple 文档识别介绍](https://developer.apple.com/videos/play/wwdc2025/272/)

Paddle PP-StructureV3 提供版面与表格分析能力，可作为另一条实验路径；仅启用任务所需模块，并测量依赖、加载、内存与准确率成本。[Paddle 官方说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/PP-StructureV3.en.md)

## 八 字段准确率与内部复核证据

### 分字段处理

| 字段 | 处理方式 | 防止的错误 |
| --- | --- | --- |
| 卷号与视频码 | 根据列位置、预印前缀、识别候选、素材目录及场记 CSV 校验 | 跨机位错配、C0 前缀丢失、数字字母混淆 |
| 场镜次 | 依据列边界、合并格和相邻行关系读取；保留字母后缀及多场次表示 | 把次当镜、漏掉十位、错误继承 |
| 过／保／废条 | 只分析实际状态格；必要时使用符号分类器 | 表头示例、折痕、污渍被当成状态 |
| 拍摄内容与备注 | 中文／英文识别、领域词典与按需语言纠错 | 术语误读、过度编号化修正 |

Vision 多候选先针对困难编号字段试验；不必为所有文字永久保存大量候选。编号列与自然语言列分别验证语言纠错策略。customWords 依赖语言纠错开启，适合作为术语增强而非通用编号校正开关。[Apple customWords](https://developer.apple.com/documentation/vision/vnrecognizetextrequest/customwords?language=objc)

去表格线、二值化、对比度增强都保留原图对照，仅在质量信号触发时生成少量变体。不要把细数字笔画一起去掉，也不要对每格无条件运行全部变体。

### 领域校验

利用现有素材清单、场记 CSV、序列异常与格式规则筛选候选。证据来源优先级沿用明确的当前业务契约；变更需单独说明。模板只提供布局，不提供上次拍摄的实际值。

素材目录可能尚未导入完整，清单缺失不能证明纸上不存在。场镜次不连续、视频码跳号也可能是真实情况。顺序规律只形成复核信号，不自动补出纸上没有的素材记录。

### 证据与置信度

内部按复核需要保留来源页／区域、原始候选与规则信号，用于覆盖检查、定向请求及评测诊断。其生命周期与当前任务和现有数据保护机制一致，不扩展为新的完整字段证据存储系统。

产品沿用现有结果编辑和原稿查看，不新增逐字段候选、来源定位、采用理由或逐字段确认交互。人工校对结果可在独立评测中形成真值；本地模型训练与长期反馈学习仅保留为后期研究。

## 九 识别速度与资源使用

### 引擎生命周期

将模型资源生命周期与一次任务分开，由现有识别运行时持有按有效配置分组的引擎资源。任务持有自己的输入、取消令牌、进度和结果；项目切换排空任务、清理项目数据缓存，模型权重可按资源策略保留。

不能直接把 MediaOCRWorkflow 改成全局单例：它当前有单个 active 任务和替换时取消前任务的语义。应在引擎／worker 层复用资源，任务工作流仍独立。沿用 OCRLeaseCoordinator 的准入与关闭机制，防止取消一个等待者影响其他任务。

Paddle 同配置 worker 在连续任务间复用，增加空闲释放、内存压力释放、应用退出关闭和配置变化失效。预热只在用户已启用且环境可用时执行，不因无关操作隐式安装或下载模型。故障恢复保持有界，不以无限重启掩盖错误。

### 分层缓存

| 缓存层 | 键的主要组成 | 不应触发该层重算的变化 |
| --- | --- | --- |
| 页面准备 | 源内容摘要、页码、渲染／预处理版本及有效配置 | 提示词、输出字段位宽 |
| OCR | 页面或区域精确内容摘要、引擎／模型版本、有效 OCR 配置、区域几何 | 仅 Provider 提示词变化 |
| 结构分析 | 全页结构证据摘要、特征版本、结构检测配置 | 场镜次规范化位宽 |
| 模板匹配 | 结构描述、匹配器版本、项目模板快照修订 | 不影响模板库的记录备注编辑 |
| 模型阶段 | 图像与证据、实际 Provider／模型配置修订、提示词、相关场记 CSV、模板及字段规则版本 | 不影响该阶段输入的其他页变化 |

原始 OCR 与模板匹配缓存分开，避免模板更新迫使 OCR 重算，也避免新模板库继续复用旧匹配结果。Vision 缓存需包含可取得的请求 revision／系统版本信息，模型更新不得沿用旧结果而不留版本依据。

缓存先实现有容量限制的项目级内存缓存，再评估持久阶段工件。磁盘证据必须遵循现有项目加密、导出、删除和数据根策略，不能另建含原稿的无保护共享缓存。内容哈希用于精确复用；感知相似度只用于候选提示，不能直接返回另一份场记单的识别结果。

### 流水与并发

按阶段采用有界队列，在页角色／模板已确定后，让下一页准备或 OCR 与上一页模型请求重叠。每阶段限制在途页数和像素／字节预算，失败和取消时排空，不发布半份结果为完整任务。

Vision 并发从当前串行基线开始，对 1、2 等小规模配置做实测，再决定是否调整；框架内部已有并行，外层增加任务可能只增加内存和争用。Paddle 分别评测模型加载、检测、识别 batch 和进程通信，不根据预设名称推断速度。

高精度模式每页可能同时发出主识别和查漏请求，因此限制应计算实际阶段请求数，不能只看页并发数。Provider 限流与本地 CPU／内存预算分别管理。

记录缓存命中、模型加载次数、worker 启停次数、阶段排队时间和处理时间。只在剖析表明 JPEG／Base64 往返占比显著时，评估内部位图交接或受控临时文件协议，不为潜在小收益先替换整个进程协议。

## 十 自适应查漏与模型调用

标准和高精度模式的现有语义先保持。新增策略先在影子评测中计算“哪些页面／区域需要升级”，只有证明不增加关键漏行和误接纳后，才作为独立自适应模式开放，不静默减少高精度校验。

升级条件同时考虑文字质量、结构覆盖、已填写格覆盖、关键字段空缺、素材键重复、跨机位冲突及不同来源不一致。OCR 未检测到的文字没有低分可供触发，覆盖检查必须独立于已识别文字列表。

按成本逐级处理：全页初识别 → 关键区域高清重识别 → 按需第二引擎／变体 → 定向模型复核 → 人工确认。每个区域有尝试次数和耗时上限；失败保留未知，不无限重试。

升级仍尊重引擎启用与 required 配置：不调用已禁用的引擎、不隐式安装第二引擎，必需引擎失败保留现有错误语义。不同引擎的原始置信度须分别校准，不能直接以数值大小选胜者。

full evidence 与 core evidence 分开生成，去除跨视图重复内容，按当前页及相关素材键选择 CSV 上下文。核心证据筛选依据字段区域和任务，不只依赖短文本／数字启发式；保留来源框和省略提示，不能为了缩短输入丢失候选素材行。

同模型两次一致不等于两个独立证据。对高风险字段优先使用不同图像视角、不同处理或第二引擎；最终复核只裁决有来源支持的记录，沿用当前“不恢复未确认字段”的保护。

完全本地的最终结构化结果作为后期实验：先针对已确认模板、关键字段齐全且有可靠几何证据的页面构建确定性路径；遇到自由手写和复杂语义仍可进入已配置模型或人工流程。离线配置不得静默转发远端服务。

## 十三 验收标准

### 必须满足的行为约束

| 用例 | 预期结果 |
| --- | --- |
| 同模板更换日期、卷号、场镜次、备注和填写行数 | 正确家族不变，或证据不足时保持未确定；不得仅因此新增正式模板 |
| 同页改变扫描尺寸、允许范围内倾斜／透视和标准／高精度模式 | 在可读测试夹具中归属不变，来源定位一致 |
| 同模板一页／多页、页面顺序变化；一个 PDF 混合模板 | 按页正确归属，文件组合不生成独立模板身份 |
| 字段顺序、机位区块或继承语义实质不同 | 不误合并为已有家族 |
| 表头缺失、照片模糊、两家族得分接近 | 进入明确的不确定结果，不新增正式模板，不输出虚假的满分 |
| 同一输入重复运行或取消后重试 | 正式模板数量稳定；独立样本计数不膨胀 |
| 家族合并、撤销、关闭重开、导入导出 | 旧任务和显式模板引用可解析，配置冲突不被覆盖 |
| 改提示词、改一页、改引擎配置、改模板修订 | 只失效依赖该变化的缓存层，结果无陈旧复用 |
| 取消等待中的任务、切项目、关闭应用 | 取消等待者不影响活动持有者；切项目和退出排空对应作用域任务，晚到结果不写入已关闭项目 |
| OCR 识别全漏某行、状态为空、视频码模糊 | 覆盖检查或复核能报告风险；不靠编号规律补造记录 |
| 运行冻结快照评测 | 正式库零写入；重复与换序运行的确定性本地阶段结果一致 |

### 初始量化目标

以下是拟定的首轮目标，不是已取得的结果。WP0 完成后结合样本量与基线形成冻结验收表；发现目标不适配时记录原因与范围，不通过降低质量要求掩盖失败。

| 维度 | 拟定目标 | 必须同时检查 |
| --- | --- | --- |
| 已知模板自动归属 | 覆盖率至少 95%，已自动归属样本正确率至少 99% | 各家族／扫描类型结果、统计区间、未知家族误接纳 |
| 确定性模板回归 | 必需同模板变体全部通过；明确不同结构负例零误合并 | 模糊样本可保留未确定，但不得算作复用成功 |
| 正式模板数量 | 已确认家族样本批次不产生重复正式家族；不确定样本零自动新建 | 不得靠把所有样本挂到一个家族满足数量要求 |
| 记录与关键字段 | 素材 precision／recall 不退化；主要关键字段错误相对基线降低至少 30% | 基线错误很少时报告绝对错误数；困难分层和误接纳不得恶化 |
| 热重复任务 | 同一会话、缓存未淘汰时，同输入同配置第二次运行无新增 OCR 推理与模型初始化 | 命中键正确；内存压力释放后允许重算；模型阶段若配置变化仍需正常重跑 |
| 性能 | 代表性重复／多页工作负载的本地阶段 p50 降低至少 30% | 冷启动、p95、峰值内存、能耗与吞吐单列；不把云端延迟算作本地提速 |
| 校对成本 | 每 100 条记录的实际校对时间降低至少 25% | 采用相同标注与复核流程，并计入新增确认动作 |
| 自适应模式 | 关键记录质量不低于冻结的严格模式验收标准，重处理量有可测下降 | 不用大量留空或降低自动通过覆盖率换取表面准确率 |

性能对照固定构建模式、硬件、系统、引擎／模型版本、数据和配置。首轮每组至少重复 5 次用于筛查，正式 p95 需要足够数量的批次／请求，不能用少量重复得出可靠尾延迟结论。

## 十五 上线与回退

算法、缓存、图像准备和自适应复核分别可控，并在诊断中记录实际启用版本；这些是内部版本契约，不先扩展成大量面向用户的参数。

上线按“离线回放 → 隔离影子评测 → 单项目主动启用 → 扩大启用”推进。影子阶段只运行确定性本地比较，不额外发送真实 Provider 请求；需要真实模型对照时采用独立、明确的评测安排。

任一阶段出现跨家族误关联、旧引用失效、缓存陈旧结果、取消后写库或关键素材误回填，都应停止扩大启用并回退对应模块。模板疑难时优先回到通用识别，缓存异常时重新计算；不得回退成“任何不确定都创建正式模板”。

迁移与家族合并按第五节处理。备份可恢复、别名可撤销和旧任务可读取，是开放新写入前的门槛。发布、远端 CI 和真实费用模型测试按项目现有授权与发布流程执行。

| 实验 | 适用前提 | 进入产品的条件 |
