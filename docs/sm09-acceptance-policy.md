# SM09 完成范围与验收分层

生效日期：2026-10-27。验收策略版本：2。

用户已要求修订 SM-09 完成范围与验收分层。本决策将 SM-09 完成定义为原生迁移、功能、数据兼容、资源安全及本地交付包验收完成。耗时和 FPS 目标独立跟踪；正式发布继续执行完整验收及所选渠道要求。

本决策替代 SM-09 施工包和阶段政策中“必须全部性能达标后才能完成迁移阶段”的要求，不修改历史通过记录、性能数值、必需功能用例、数据保护断言或分发签名要求。修订规则不构成任何提交的 PASS、COMPLETE 或发布授权。

## 一 验收层级

| 层级 | 入口与场所 | 必须满足 | 结果用途 |
| --- | --- | --- | --- |
| 本地开发检查 | 定向离线测试、构建、ci_preflight；不启动前台 | 受影响行为与静态契约通过 | 开发反馈，不能单独确认阶段完成 |
| 功能及迁移完成验收 | GitHub macOS runner 执行 phase_gate.sh SM-09 --functional | 原生构建、功能、数据、资源、完整必需 UI、归档及 ZIP／DMG 交付验收通过 | 合并证据；干净提交的完整 PASS 可提交 SM-09 完成审查 |
| 性能报告 | 独立 performance job，使用现有严格断言 | 如实报告耗时、FPS、内存及错误 | 对功能合并和迁移完成非阻塞；失败保留为性能待办 |
| 完整发布候选验收 | GitHub macOS runner 执行 phase_gate.sh SM-09，不加 --functional | 功能及交付检查与全部现行性能预算通过 | 当前候选的完整技术验收，不自动发布 |
| 分发渠道验收 | Developer ID 或 Mac App Store 的独立流程 | 相应签名、公证／商店签名、沙盒及上传要求 | 仅证明实际执行的渠道步骤；不等同于商店审核或发布授权 |

功能 Gate 的检查范围保持不变。默认不带 --functional 的命令仍是严格完整 Gate，release.yml 继续使用该入口；性能 job 的失败不会被改写为 PASS。

## 二 SM09 完成必须满足的要求

1. 原生源码与历史迁移证据可追溯；保留的夹具、替代测试和旧输入删除映射通过现有审计。
2. SwiftPM 与 Xcode Debug／Release 构建通过，当前交付目标仍为 macOS 15 及 arm64＋x86_64 Universal。
3. 项目、任务、识别、设置、元数据和 CSV 的必需核心回归通过；旧项目导入、编辑、关闭重开及重新导出保持数据与源包保护。
4. OCR 可用性、必需／可选失败语义、取消、项目切换和关闭排空验证通过；不得留下无归属工作、进程或计时器。
5. Debug 与打包 Release 的必需原生 UI 用例实际执行并通过，保留逐项覆盖和零跳过要求。搜索清空、中文输入、窗口、原稿翻页等真实功能失败仍阻断完成。
6. 内存、可见行／视图数量、虚拟化及资源释放的现有保护继续执行。仅计时和 FPS 项按 functional 策略分离。
7. 真实 App 隔离启动、Release Archive、bundle 资源／依赖／entitlements／签名审计、ZIP／DMG 同源及打包 App UI 回归通过。
8. Gate 从干净候选提交开始并在结束时确认同一提交与工作区；日志、xcresult、覆盖报告及最终结果完整一致，无未执行的前置依赖被当作成功。

以上任何必需项为 FAIL 或 BLOCKED_ENV，均不能确认完成。NOT_RUN 表示没有执行，不能代替 PASS。普通离线测试、旧提交的报告、未跑真实流程的静态检查都不能代替这组验收。

## 三 完成证据与发布证据

result.json 增加以下字段，现有 schemaVersion 保持 1，以附加字段区分策略版本：

| 字段 | 含义 |
| --- | --- |
| acceptancePolicyVersion = 2 | 使用本决策的验收分层 |
| completionEligible | SM-09 完整运行已结束、结果 PASS、不是脏工作区诊断，且检查列表有效、没有失败或未执行项；可提交阶段完成审查 |
| fullAcceptancePassed | 同时满足 completionEligible、full 范围及现有严格 Gate 可批准条件 |
| approvable | 保留既有完整 Gate 的含义；functional 模式仍为 false，避免旧消费者把功能证据误认为完整发布证据 |
| scope 与 performancePolicy | 保持 functional／advisory 或 full／required 的实际范围 |

因此，干净 functional PASS 的合法组合是 completionEligible=true、fullAcceptancePassed=false、approvable=false。这个组合可以支持迁移阶段完成审查，但不能用于宣称完整性能验收通过。

运行中、取消、失败、环境阻塞、脏工作区、空检查列表、只有不适用项或含 NOT_RUN 的结果，均不能获得完成资格。native-evidence.json 中原有 completeAcceptance 仍表示完整严格验收；functional 下继续为 false，它不是新的阶段完成字段。

旧结果没有新策略字段，不自动升级为新策略的完成证据。离线回放继续标记为历史回放；独立 UI 覆盖、源码提交和证据有效性仍按原检查执行。

## 四 阶段状态的推进

当前 CURRENT_STATE.json 仍为 REVIEW_READY。本次不填入虚构的 reviewCommit，不复用历史批准，不修改其 PASS／COMPLETE 状态。

完成流程为：

1. 将本次验收政策、相关代码和测试固定在可审查的提交上。
2. 在 GitHub macOS runner 对该提交执行完整 functional Gate，保留所有必需功能、资源和打包检查；要求最终 completionEligible=true。
3. 核对同一提交的结果、必需用例执行情况、包与源码身份、未解决功能问题以及独立性能报告。性能失败以指标、影响、跟踪位置和后续验证安排记录，不改成通过。
4. 将技术结论记为 PASS，范围明确写为 functional-and-local-package，策略版本为 2，并引用实际结果及报告。
5. Repository Owner 确认该范围的结果后，才能记录 COMPLETE。批准记录明确“原生迁移与本地交付完成；性能／正式分发另行验收”，且只批准对应候选提交。

记录批准所用的治理提交仍只包含状态文件和阶段 review；现有批准新鲜度与提交追溯检查继续适用。后续代码变化仍须取得自身的 CI／发布证据，历史 COMPLETE 不自动批准未来版本。

## 五 性能待办与环境条件

现有 2 秒万行处理、45 FPS 滚动、加载与编辑耗时等数值不变。共享 runner 上的性能结果依然按真实执行记录 PASS／FAIL，只是不再作为迁移完成的阻断项。完整发布 Gate 继续要求它们达标。

内存无界增长、虚拟化失效、孤儿进程、关闭未排空等资源正确性问题始终阻断功能 Gate，不能归为非阻塞的“性能优化”。

需要重新制定性能指标时，另行基于目标设备、Release 配置、冷热状态和足够样本记录决策。不能为当前失败临时扩大阈值或更改工作负载。

runner 无法提供实际宽屏尺寸时，明确记录实际执行尺寸和未覆盖场景。最低窗口、可见性、点击、键盘和功能断言保持有效；将来调整屏幕验收矩阵需要独立覆盖决策，本轮不删减或放宽现有 UI 检查。

## 六 执行与产物位置

本机新增的测试、日志、截图、临时文件、构建缓存、DerivedData 和 xcresult 统一放在 ${SLATESYNC_VALIDATION_ROOT} 下，以每轮独立子目录保存。设置 TMPDIR、RUNNER_TEMP 和各工具输出路径，并检查脚本内部写入点；只设置 --results-dir 不能保证所有构建和临时文件都进入目标目录。

`SLATESYNC_VALIDATION_ROOT` 表示使用者指定的仓库外验证目录，例如 `${TMPDIR:-/tmp}/slatesync-validation`。文档中的 `<source-pdf-root>`、`<ground-truth-root>` 等均为本地私有输入目录占位符，公开文档不记录个人账户、设备目录或签名身份。

## 历史证据的隐私脱敏

2026-10-28 的隐私修订仅改变历史证据副本中已列明的个人信息。原始 Git 对象、封存清单和原始 SHA-256 保持不变；`sm09-privacy-projection.json` 以固定的 UTF-8 字节范围和替换文本定义当前副本，策略本身由校验脚本固定哈希。当前副本必须与从原始证据生成的投影逐字节相同，不使用泛化正则忽略其他差异。

历史目录继续检查全部文件、文件模式、HEAD、暂存区与工作区。HEAD 和暂存区只允许原始版本或精确脱敏版本，以支持本次未提交修改和后续提交；工作区必须为脱敏版本。新增、删除、修改其他内容、篡改验收结果或封存清单仍失败。既有兼容性、覆盖率、来源、断言与性能门槛不变。该修订不改写 Git 提交历史，也不构成新的验收 PASS。

本机继续只做离线自测、静态检查与所需构建；未获得专门的前台验收安排，不运行完整 Gate、XCUI 或前台性能测试。远端使用 runner 的隔离产物根并上传证据，下载到本机的副本放入上述 1027 目录。

历史证据中记载的 /tmp、/private/tmp 和旧 Gate 路径保持原样，不能将历史记录改成并未实际使用的新路径。本政策仅约束新生成产物。

## 七 本轮变更边界

同步修改 SM-09 包的现行说明、PHASE_GATES、总兼容契约的范围引用、开发／发布说明及 Gate 结果元数据。保留历史 review、封存 manifest、CURRENT_STATE、全部功能用例、严格性能阈值、release.yml 和渠道签名行为。

验证使用合成 Gate 结果及现有离线自测，覆盖功能通过可用于完成审查、完整验收独立标记、脏／失败／未完成／空证据不获得资格，以及发布工作流不能转为 advisory。离线自测通过只说明分层逻辑正确，不是当前应用已经完成 SM-09。
