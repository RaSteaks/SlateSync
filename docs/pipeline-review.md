# 场记识别与元数据回填审查（2026-10-21）

范围：原生输入 → OCR/模型 → 逐页复核与归一化 → 人工编辑 → 素材匹配 →
sidecar 回填 → 对账预览 → CSV 导出，以及本机 stdio MCP 接口。
本次没有在本机启动 App、XCUI 或前台性能验收。

## 已修复问题

| 问题与触发条件 | 原行为 / 影响 | 修复与验证位置 |
| --- | --- | --- |
| 手工编辑 CSV 的 File/Reel/Clip 标识 | 扫描按新标识查找，导出仍按原始标识回填，可能把旧素材字段写进新素材行 | 标识编辑先参与匹配；其余字段最后覆盖。`PipelineSafetyTests.testEditedIdentityIsUsedForRecognitionAndSidecarMatching` |
| 同素材存在完整记录和字段矛盾的不完整记录 | 不完整记录先被过滤，冲突被忽略，完整记录照常写入 | 全部可用字段先参与冲突判定；有效 FPS/日期继续独立回填。`testIncompleteContradictoryDuplicateCannotBeIgnored` |
| 同一模型轮次重复输出同素材且值冲突 | 保留第一条掩盖矛盾，第三轮也可能按响应顺序裁决 | 重复核心字段冲突留空；主识别/查漏内部冲突进入定向复核；第三轮冲突保持未确认 |
| 查漏候选第三轮确认存在，但某字段仍看不清 | 第三轮 null 会保留查漏阶段的旧猜测 | 确认存在与确认字段分开处理；第三轮未知字段留空并标记复核。`testAuditOnlyReviewCannotReviveUnconfirmedValues` |
| 同素材目录存在多个 slate.txt 副本 | 第一个模板命中就返回，漏掉后续冲突文件 | 收集全部受支持候选，由合并器按字段对账；保留命名学习统计 |
| 通用 camera-slate.txt 被放进错误素材目录 | 只核对文件名与 Clip Name，没有核对所在目录；可能回填另一条素材 | 同时验证目录归属和当前 CSV 目标集合；根目录只有命中目标集合时才按素材目录处理 |
| 所有识别记录不完整或冲突 | 预览复用导出守卫而直接报错，无法看到具体状态 | 新增共享 `previewMerge` / `previewResolve`；预览可用，导出守卫保留 |
| 手工 edit 行列越界 | 不生效的 edit 仍能绕过“有可导出记录”的守卫 | 原生与 MCP 共用 `permitsExport`，只认可表内有效编辑 |
| 导出计算期间切换任务或提交新单元格编辑 | 导出不受取消/排空管理，可能发布旧任务文件和诊断 | 导出纳入 cancel/join、表身份和编辑代际校验；重复导出拒绝；确认文件绑定原表 |
| 自动纠错记录、无法识别的 CSV 行 | 待复核标记可能没有进入导出确认计数 | 统一 `reviewIssueCount`，新增 `review-required` 状态；用户编辑某核心字段只清除该字段标记 |
| 大量告警超出 UI 截断数量 | UI 提示“其余见日志”，但日志只记录数量，用户无法查看正文 | 共享完整报告 sheet，保留全部文字并支持选择复制；覆盖信息即使没有错误徽标也可查看 |

## 后续可提升项

1. **可追溯证据与逐字段确认**：目前记录保留页码、置信度、复核标记和告警，
   但表格没有逐字段跳转 OCR bbox / 图像区域，也没有“确认原值”的专用动作。
   下一步宜让诊断条目定位到素材行和对应原稿，保留修改前后值及确认来源。
2. **区分未扫描和扫描后零结果**：合并 API 当前以元数据数组表示输入；空数组
   不能表达扫描意图。扫描报告保留 missingKeys，但合并器不会单凭空数组要求
   FPS/日期齐全。后续可显式传入扫描上下文，使原生与 MCP 一致表达此状态。
3. **场记 CSV 的辅助元数据**：解析器读取 Camera FPS/Shoot Day，但本地记录
   投影只保留场记字段，回填仍取 sidecar。若要启用这些值，先明确与 sidecar、
   手工编辑的来源优先级并记录冲突，不能静默覆盖。
4. **版式驱动局部图**：现有局部图使用固定核心列裁切，Profile 主要增强提示词。
   可以基于已验证列区域选择局部图，配合真实多版式标注集评估漏行率和字段准确率。
5. **可恢复识别与成本可见性**：当前已完成页缓存属于运行时，未形成重启后恢复
   的持久阶段工件。可进一步按输入摘要/配置版本缓存 OCR 和页面结果，并明确
   重试将重跑哪些页、预计请求数和实际用量，避免用降低校验轮次换速度。
6. **MCP 桌面任务协同**：本轮提供无项目库副作用的单次处理工具。若后续要操作
   当前 GUI 项目，应通过应用内 RPC/单写者队列与编辑保存屏障协作，再扩展工具；
   不应让第二个进程直接覆盖 GUI 正在自动保存的任务。

保留的业务边界：场记视频码仍按 C0XX 识别；Resolve 统一素材键仍按数值卷号/
条号匹配；自由备注不会自动写入 Resolve Comments；只有 FPS/日期回填不能单独
通过导出守卫。扩展这些边界应有明确格式/来源契约和迁移测试。
