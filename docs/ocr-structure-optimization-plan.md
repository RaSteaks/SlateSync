# 场记单结构识别优化方案

修订日期：2026-10-29。版本：测试收敛版。状态：代码与离线回归已完成，真实效果和发布验收待执行；详见[实现状态](ocr-structure-implementation-status.md)。技术调查基线：`2d732744ac161d9032c1c215f60f176ea3a28667`；评测时另行冻结实际代码与配置。

本方案细化四项工作：动态裁图、行列与合并格证据、减少图像编码损失、按冲突区域复核。目标是降低场记单的漏素材、错机位／错卷、场镜次错列及状态符号误读，同时控制请求量、内存和处理时间。

实施顺序为：最小基线与坐标契约 → 动态裁图 → 结构证据 → 定向区域复核。无损图像实验在基线完成后独立开展，有收益才接入。每项先做定向回归和小样本筛选，最后仅比较现有流程与一个最终候选；未证明收益的路径保留为实验，不改变默认识别行为。

本次修订取消 A～F 全组合必跑、每组固定三轮、开发前完整标注及新增性能倍数门槛。验证按第九节的触发时机执行；第四至七节的完成条件用于阶段决策与最终采用，不要求每次修改都执行全部评测。仓库既有必需检查和业务断言继续保留。

本方案是[本地识别优化总方案](local-recognition-optimization-plan.md)的专项补充，沿用其短期项目无需学习模板、原稿只读、人工真值隔离及本机离线验收要求。本专项的样本规模、重复轮次和本地检查频率以本次修订为准；其他优化仍由总方案管理。新增设计不表示现有实现契约已经变更；实现前将具体数据与行为边界同步到[识别实现演进决定](recognition-contract-evolution.md)，旧夹具和历史验收证据保持原样。

## 一 当前流程与改进依据

当前先完整准备 PDF 页面与视图，执行本地 OCR 和逐页版式匹配。标准模式执行一次视觉模型主识别；高精度模式并行执行主识别与独立查漏，必要时再裁决冲突。最后跨页合并、归一化字段并进入人工校对。

| 环节 | 当前代码事实 | 本方案处理 |
| --- | --- | --- |
| PDF 渲染 | 处理页面框、UserUnit 和 PDF 旋转；比例最高为 4，最长边限制为 3000 | 保留原生渲染；原图提取及自动纠斜属于总方案中的相邻工作 |
| 页面图像 | 去上下空白后，全页编码为最长边 2600、质量 0.92 的 JPEG | 保留全页参照；独立比较同尺寸的有损和无损输入 |
| 局部视图 | 顶部 22% 作为表头，正文上下分段；均取左侧 62%，拼接后最长边 3000 | 依据当前页的表头、表格线和机位区域选择裁图 |
| 表头定位 | 已有场、镜、次、视频码与机位锚点，主要用于版式匹配和提示 | 复用语义和锚点，不以保存或确认模板作为裁图前置条件 |
| OCR 证据 | 文字、置信度和视图内坐标；尚无完整行列及合并格结构 | 增加有限的内部结构证据，并保留无法分配的文字块 |
| 高精度复核 | 主识别与独立查漏并行，冲突及查漏候选进入裁决；各阶段已有全页参照 | 保留调用阶段，优先改变裁决时的局部图选择 |

代码依据：[PDFRasterizer](../Sources/SlateSyncMedia/PDFRasterizer.swift)、[PreparedImageEncoder](../Sources/SlateSyncMedia/PreparedImageEncoder.swift)、[ImagePreprocessing](../Sources/SlateSyncMedia/ImagePreprocessing.swift)、[ScenarioStructureMatcher](../Sources/SlateSyncWorkflow/ScenarioStructureMatcher.swift)、[MediaOCRWorkflow](../Sources/SlateSyncWorkflow/MediaOCRWorkflow.swift)、[RecognitionPagePipeline](../Sources/SlateSyncWorkflow/RecognitionPagePipeline.swift)。

已有评测使用 16 页输入，其中三份首页的 52 个物理行、156 个场／镜／次单元格用于固定字段评分，原始 OCR 严格正确为 40/156。86 个未分配单元格中有 55 个与跨格文字框相交。这支持优先研究结构归属，但不等于最终记录准确率或素材漏行率。完整口径见[既有 OCR 对照记录](recognition-optimization-progress.md#2026-10-27-实际优化前后-ocr-对照)。

## 二 范围与保持不变的行为

- 保持 macOS 15、现有模块分工、Vision 优先和可选 PaddleOCR，以及 required／optional OCR 的失败语义。
- 保持最多 20 页、每个识别阶段每页最多 3 个视图。第一个视图始终为全页，其余最多两个为局部图；不能通过新增请求绕过该预算。
- 标准模式仍执行一次主识别，不为了布局增加云端调用；高精度模式仍执行主识别、独立查漏和按需裁决。不在本方案中启用自动跳过查漏。
- 保留全页上下文、未知字段留空、素材身份一致性、输出截断判失败与备用模型机制；保留 CSV 编码、字段回填及人工校对行为。
- 不安装 OXR、D-FINE 或新的本地模型，不引入外部 OCR 服务依赖，不复制其带附加许可证的实现代码。借鉴的是区域识别、结构表示和有界调度的设计。
- 不新增字段证据产品界面，不要求用户命名模板，不改变项目库和项目包版本，不重写历史任务、原始 PDF 或人工 CSV。
- 原始扫描图提取、自动方向校正、跨阶段流水及持久缓存继续由总方案管理，不作为本专项全部完成的前提。接入这些能力时必须沿用同一坐标和输入身份契约。

## 三 共同基础与数据边界

### 页面坐标与局部图映射

以应用 PDF 页面框和旋转之后、去空白之前的显示页作为统一坐标系，原点位于左上角。完整记录去空白偏移、缩放和裁图区域；识别视图保留自己的像素尺寸与局部归一化坐标。

新局部图优先采用连续矩形行带，不拼接不连续区域；需要上下文时使用同次请求中的全页图。若保留表头拼接，必须分别记录表头和正文的来源矩形、目标矩形，不能将整张拼接图当作一次缩放。跨越拼接边界的 OCR 框不得强行投影为一个原页单元格。

映射信息是本次任务内部值，不进入模板身份，不跨页复用。旧任务只有 JPEG 视图而缺少原页或映射时，沿用原视图识别；不能反推拼接位置或宣称恢复了原始分辨率。

### 类型与模块职责

| 所属模块 | 职责和最小数据 |
| --- | --- |
| SlateSyncDomain | 表达页面／视图身份、矩形映射和结构证据；不持有 PDFKit、Vision 或可变图像对象 |
| SlateSyncMedia | 页面渲染、图像字节、表格线几何、裁图与图像格式边界；图像对象在其执行上下文内解码与释放 |
| SlateSyncWorkflow | 结合 OCR 表头与几何生成裁图计划、分配结构证据、选择复核区域及组织实验诊断 |
| SlateSyncPersistence | 继续保存现有任务结果与 JPEG 输入；本专项不增加结构证据表或修改历史序列化 |

结构证据只包含定位需要的表格区域、列角色、物理行、机位区块、合并范围、关联文字块及不确定原因。几何可靠程度、OCR 文字置信度、模型字段可信度分别记录，不互相冒充。新类型仅在真实调用边界需要时添加，不建立通用文档解析框架。

### 缓存与任务生命周期

原始 OCR 缓存继续保存视图内结果，依据项目、引擎、有效配置、尺寸和实际输入内容区分；增加无损格式时同时区分编码格式。相同局部像素可以复用 OCR，但投影和结构结果必须重新使用本次映射，不能复用其他页面的行列身份。

识别恢复键纳入实际发送图片、提示和结构／裁图策略版本。策略变化不得命中旧的结构化结果。保留现有有界 LRU、项目隔离、取消、排空与 Paddle 租约；新增裁图不要求全部常驻缓存。

全页和局部 OCR 共用一次任务的累计时间预算，新增阶段不重置已消耗的等待时间。任一阶段取消时终止后续裁图与请求，进度保留已完成数量，不因第二轮局部 OCR 退回零。

每页高质量源图在本地处理时有界持有；需要晚期复核时按需重新读取并核对输入摘要。原稿改变、不可读取或历史任务缺少原稿时回退现有视图，不保留 20 页解码大图直到云端完成。

## 四 动态裁图

### 处理过程

1. 准备全页图，先执行一次全页 OCR。使用已缓存的全页结果时不重复推理；标准模式到此仍只保留全页输入。
2. 复用现有表头字段识别规则，在全页范围寻找场／镜／次、视频码、状态栏及机位锚点。结合低分辨率的长横线、竖线与内容分布定位表格候选；像素分析不增加云端请求。
3. 检查锚点顺序、机位区块、表格边界和覆盖范围。表头中心不能直接当作列边界；断线、低置信度、多表格或字段冲突均保留不确定状态。
4. 为高精度模式选择最多两个连续行带，尽量覆盖共享场镜次列以及对应的所有机位视频码和状态列。分段边界留重叠与安全边距，避免切断手写字符或合并格；顶部卷号和日期始终保留在全页参照中。
5. 对新增局部图按需执行 OCR，与全页结果一起形成证据。局部图覆盖不足时保留全页扫描要求，不能将未覆盖区域判断为空白。

首版在最多两个局部图内优先覆盖完整表格的上下行带。若表格过宽、机位过多，无法同时保证局部可读性和覆盖，记录该限制并回退兼容裁图，不无限增加图块。宽度改为 100% 只作为对照方案，不能凭直觉替换所有页面。

全页 OCR 失败但为 optional 时继续原有图片识别路径，不增加第二次相同失败请求；required 失败继续终止。无可靠布局时使用既有裁图策略和全页参照。

### 代码范围与交付

- 在 `MediaPreparationService` 与 `MediaOCRWorkflow` 之间拆分全页准备和后续局部图准备的时序；保留现有兼容入口。
- 在 `ImagePreprocessing`／`PreparedImageEncoder` 附近加入几何检测、连续裁图与映射，复用已有编码能力。
- 复用 `ScenarioStructureMatcher` 的表头语义，但不在媒体模块依赖 Workflow 或模板持久化。
- 更新受影响的坐标、视图及缓存注释；新增裁图计划、回退原因和覆盖叠图供离线核查。

完成条件：可靠布局夹具中，所有人工标出的目标列均被计划覆盖；真实右侧机位与非标准表头样本的记录召回不劣于基线；没有裁掉卷号、日期或状态符号；布局失败能恢复兼容行为。

## 五 行列与合并格证据

### 结构生成与使用

在动态裁图的坐标基础上，从表格线、表头及文字分布恢复列区间和物理行。识别共享字段区与各摄影机子区，将文字块关联到可能的单元格；跨多个单元格的文字块保留原框和候选关联，不凭框中心唯一分配，也不按字符数量机械切开。

合并范围需要边界、邻行或多项布局证据支持。单独出现空白不能证明合并；缺失表格线也可能是浅色扫描或手写遮挡。无法确定时不自动生成 `rowspan`，维持未知并交由图片识别。

输出采用紧凑内部结构，表达行／列编号、机位、合并范围及文字块来源。无需先转换完整 HTML 再解析；如未来评测 OXR 输出，需独立适配其表格结构，不能把区域级 bbox 当作单元格 bbox。

例如一处“02 镜”可能覆盖四个物理行，每行具有 A／B 机素材。结构层提供这些行与镜号单元格的关系，业务层仍逐条读取视频码、Take 和各机位状态。文本相同不代表同一素材，重叠裁图产生的重复观察只能按来源和几何合并。

### 分阶段启用

先只输出诊断，与人工行列标注比较；随后向主识别提供有限的几何提示和明确标注的 OCR 证据。字段最终值仍须核对图片，不能由结构层直接覆盖。

独立查漏不接收主识别结果、推断继承值或共享的模型生成答案；仍从全页逐机位盘点。若使用同一几何提示，必须要求检查提示以外区域，不能把“主识别与查漏都未看到”当作不存在的证据。

结构核验用于发现错列、越界继承、跨机位赋值等风险，并引导复核。首版不替换 `RecognitionPostprocessor` 的既有跨页继承算法；若后续需要更改自动继承，单独形成行为契约与真实回归证据。

主要涉及 `OCRModels` 或相邻领域值类型、`ScenarioStructureMatcher` 的可复用语义、`OCREvidenceFormatter`、`RecognitionPrompts` 和 `RecognitionPagePipeline`。结构描述仍受提示词及完整请求预算约束，优先保留核心字段，不让大量结构文本挤占图像预算。

阶段完成条件：结构误关联和合并格范围有人工可核查记录，结构定位指标改善，且不新增错卷、跨机位字段继承或猜测补值。无法判定的比例与正确率同时报告。默认启用还必须通过第九节的业务字段质量门槛，不能仅凭结构分数提升决定上线。

## 六 减少图像编码损失

### 独立实验

使用同一次渲染、相同裁剪、像素尺寸、颜色处理、OCR 配置和模型配置，仅改变编码。基线沿用全页 JPEG 质量 0.92、局部图质量 0.93；无损组从 JPEG 编码之前的图像生成 PNG。局部图同样保持几何与尺寸一致。禁止将现有 JPEG 转成 PNG 后称为无损源图实验。

先在开发小样本上比较本地 Vision 的文字和关键符号结果；只有观察到收益且需要评估云端格式时，才在相同 Provider 图片格式能力下测试云端输入。局部放大不产生新的原始细节；源图已低清或有 JPEG 压缩损失时，无损编码只能避免新增损失。

首轮记录正确字段、漏检、状态符号混淆、文件字节数和本地处理耗时；生产接入涉及解码或图像持有变化时，再补一次有界内存对照。小样本未见收益则暂停本项、保留 JPEG，不追加云端实验；该决定不外推为所有样本都没有收益。

### 生产接入条件

当前 `PreparedImage` 明确是 JPEG 容器，且被历史保存、恢复、Provider 传输和 Paddle 协议使用。首个实验不放宽其校验；通过独立开发入口比较无损输入。

确认收益后，优先新增仅供本地 OCR 的最小图像输入边界，包含编码字节、格式和尺寸；在媒体执行上下文内解码，不让非 Sendable 框架对象跨模块流动。Provider 传输与历史任务仍使用兼容的 JPEG，避免全链路格式迁移。

Vision 原生、Vision 外部 bridge、Paddle 三条路径明确各自支持格式；不支持者使用兼容 JPEG，并在诊断中记录实际路径。无损收益不能从 Vision 实验外推到其他引擎。缓存使用实际 OCR 输入内容，避免误命中旧 JPEG 结果。

云端 PNG 仅在独立实验显示端到端收益且 Provider 支持时另行启用；按最终 MIME 和请求体重新测量预算，超限回退 JPEG。首次本地无损接入不要求同时改动云端格式。

完成条件：同尺寸对照可重复，有明确精度收益且资源预算可接受；保存／恢复、桥接、取消及缓存隔离无回归。未达条件时将本项结论记录为“保留现有编码”，而非阻塞其余三项。

## 七 按冲突区域复核

### 复核图选择

保留现有触发条件：主识别与独立查漏有字段冲突，或查漏发现额外候选。复用本页结构证据，将候选素材键关联到物理行和对应机位；只有位置可靠时才改变复核图。

每个裁决请求继续使用一张全页图及最多两张局部图。局部图包含目标行、必要邻行、相关共享场镜次及状态列；合并格跨行时包含所属范围。卷号切换或范围视频码不能只裁单个数字。

多个冲突区域可以合并为有限行带；若两个局部图无法覆盖全部目标且保持可读性，则使用原有完整视图组合。不拆成无界的逐素材调用，不额外增加裁决轮次，不取消现有全页参照。

新图尽量来自任务内高质量页面或摘要一致的原稿重渲染。旧任务无原稿、映射缺失、定位不明或源文件改变时沿用原视图。不能仅靠模型声明的坐标或猜测条号顺序生成精准裁图。

### 与识别契约衔接

仍只复核目标素材键，图中找不到的候选不能新增记录。局部图和结构证据作为阅读辅助，无法确认的字段保持未知或待人工复核；状态空白不能自动解释为“过”。

首版不为复核裁图额外运行一整轮 OCR；已有全页／局部 OCR 按映射投影即可，不足时由图像判断。跨区域图像内容变化必须进入请求与恢复缓存身份。

主要改动 `RecognitionPagePipeline` 的裁决请求构造，并由媒体层提供按计划生成图片的能力；复用现有 Provider、请求预算、超时、重试与主备链，不另建网络调度器。

完成条件：冲突修正正确数提高，错误裁决数不增加；每页裁决调用数不超过当前流程；所有目标有局部覆盖或明确全页回退；历史任务能够沿用兼容复核。

| P0 最小基线 | 从现有 16 页选出 4～6 页开发样本，只补受影响字段与几何标注；冻结版本与坐标边界 | 复用已有标注和夹具，留出来源先隔离；不以完整标注或评测工具建设阻塞开发 |
| P1 动态裁图 | 布局与裁图计划、最多两个局部图、坐标映射、回退 | 依赖 P0；定向几何验证后，在开发样本上做一次配对筛选 |
| P2 结构证据 | 行列、机位和合并范围；先诊断、再辅助主识别 | 依赖 P1；只比较新增结构证据的效果，不重跑已淘汰方案 |
| P3 图像质量 | 同尺寸 JPEG／PNG 本地小样本对照 | 依赖 P0，可独立推进；未见收益就暂停，有收益才适配生产输入 |
| P4 定向复核 | 冲突定位、局部重裁、原视图回退与请求预算 | 依赖 P1／P2；复用冲突用例，只在确有冲突的开发页验证实际效果 |
| P5 最终候选 | 现有流程与一个候选的留出集对照、集成检查和回退说明 | 仅包含筛选通过的改动；按需增加复验，不要求全部实验组合达标 |

开关作为开发／运行时策略集中管理，默认走现有路径，不新增面向用户的参数矩阵。关闭任一实验项即可恢复对应基线行为；恢复时清除或隔离不兼容的派生缓存，不删除任务和用户数据。

## 九 收敛后的验证方案

### 分层执行与停止条件

| 层次 | 执行时机 | 执行内容 | 何时停止或扩大 |
| --- | --- | --- | --- |
| 文档检查 | 仅修改方案或文档索引，且没有行为变化 | 检查内容一致性、仓库内链接和差异空白 | 通过即结束；纯文档修订不运行构建、应用测试或完整预检 |
| 定向回归 | 修改某项生产行为后 | 复用受影响的现有测试，只补新增行为与已复现缺陷的用例 | 通过且无新疑点即继续开发；修复失败后重跑受影响范围 |
| 效果筛选 | 某项能力首次形成可用结果，或修复了已确认的识别问题后 | 在固定开发小样本上比较前后结果一次 | 无收益则暂停该实验；出现退化则定位修复；不默认扩大到全部原稿 |
| 候选集成 | 筛选通过的改动整合、准备交付时 | 全量 SwiftPM 测试、无窗口预检，以及仓库要求的 App 构建和 CI | 同一版本通过后不重复；新改动、失败或未解决的依赖风险才扩大重验 |
| 最终效果验收 | 一个候选的算法、配置和评分口径冻结后 | 候选与现有流程在独立留出集上配对比较 | 明确通过则完成；结果接近或波动时追加配对复验；仍不确定则保持实验状态 |

候选集成在仓库根目录执行 `swift test -Xswiftc -warnings-as-errors` 和 `./script/ci_preflight.sh`。同目标、同配置已由测试完成编译时，不再机械追加 `swift build`；仅对测试未覆盖的目标、构建配置或仓库明确要求单独构建。App 的 Xcode 构建不能用 SwiftPM 编译替代，按既有要求放在集成节点执行。

后续修复先跑定向回归；涉及公共契约、依赖或跨模块变化时再补相应全量检查。最终交付版本仍须通过仓库必需 CI。完整 SM-09、XCUI 和打包 UI 验收继续使用 GitHub macOS runner，不因本专项减少实验而删除现有检查或断言。

### 开发样本与留出样本

从现有 0801、0816、0904 共 16 页中选 4～6 页作为固定开发小样本，尽量覆盖多机位、合并格、低清或细小符号；一个页面可以覆盖多个问题。先复用已有 156 个字段标签，只补当前实验所需的字段、行或区域标注，不要求先标注全部页面和全部单元格。若这些页面缺少某个已知关键场景，再定向补充少量样本。

开发开始时隔离留出来源，不查看其识别结果用于调参。候选确定后，从其余来源按日期和物理原稿分组准备约 20～30 页作最终验收，同日相关场记单、日报和重复扫描归入同组；完整标注工作推迟到此阶段。样本不足时说明覆盖限制，不把开发页改称留出页。若留出结果被用于调参，该组转为开发资料，最终验收另用未参与调参的来源。

CSV 仅作评分真值，不进入纯图片识别输入。沿用已隔离的 9 组 Take 冲突；没有纸面覆盖证明的素材不计漏行，空字段未经确认不作负例。行列几何和状态空白按原稿补充标注，不能从 CSV 值反推位置。

### 四项工作的最小验证

| 工作 | 必要回归与首轮筛选 | 有证据后再追加 |
| --- | --- | --- |
| 动态裁图 | 用已知标记点与裁图像素验证坐标；检查右侧机位覆盖、全页保留和无布局回退；小样本做前后对照 | 实际发现的裁错、切字或特殊版式用例 |
| 结构证据 | 检查合并范围、跨格文字的未知处理、共享场镜次与机位关系；在同一开发样本上只增加本项 | 真实错列或错误继承的回归，不穷举所有表格形态 |
| 无损图像 | 同尺寸 JPEG／PNG 本地对照；无收益就暂停 | 有收益才测试生产接入、受影响的格式边界和内存；云端 PNG 按实际需要另评 |
| 定向复核 | 检查目标位置、全页参照、请求上限、定位失败和旧任务回退；复用已有冲突样例 | 只在有冲突的开发页验证云端裁决效果，不重跑所有无冲突页面 |

PDF 旋转、文件错误、历史恢复、缓存隔离、取消和关闭等已有回归优先复用。只有对应实现被改变或新增路径绕过了既有保护时，才补充针对性用例；多阶段 OCR 改动必须覆盖新阶段的取消与累计超时，不能用旧入口通过代替。测试使用独立期望和实际生产实现，不复制生产几何公式，不以同一实现的往返结果独自证明坐标正确。

### 对照与复验规则

开发阶段采用增量对照：当前已保留的方案与仅增加本项的方案配对，其他输入、精度模式、引擎、Provider 和配置保持一致。保留可追溯的原始基线，不为每个阶段重新执行所有旧组合。局部裁图与高精度流程比较，不能拿标准模式作为其性能基线。

首轮每个方案在小样本上各运行一次，仅作筛选。最终仅运行现有流程与一个组合候选，先完成留出集的一轮配对；同一配对固定服务配置，页面间交替执行先后顺序。若主要指标接近、出现无法解释的差异或模型波动，再增加完整配对轮次，通常累计最多三轮；仍无法判断则暂不启用，不无限重跑。

新增的复验必须保留所有轮次和同一评分口径，不只重跑失败页后挑最好结果。为诊断而单独重放失败页时，结果单列，不混入完整验收计数。冻结配置后的已有本地结果可以重放用于评分，但不能当作新的云端实测或新的性能样本。

### 指标与采用条件

日常筛选只收集关键字段正确／错误／未知、确认范围内的漏行／额外记录／错机位／错卷，以及请求数和处理耗时。裁图阶段额外看区域覆盖，结构阶段额外看误关联，复核阶段额外看正确修复与错误改写；不要求每项都输出整套性能报告。

候选采用须满足：至少一项预先指定的业务质量指标改善，其他关键质量指标不恶化；不能靠增加留空换取表面正确率。新增错卷、跨机位误写或错误确定状态须定位并解决，整体平均改善不能掩盖严重退化。数据不足或结果波动时按复验规则处理，不把一次筛选称为准确率达标。

取消原方案新增的耗时 1.10 倍、p95 1.15 倍、内存 1.25 倍门槛。仓库既有资源预算继续有效。最终候选报告已有测量中的耗时和请求量；仅在修改解码、持续持图、缓存容量或发现资源退化时追加有界内存／性能对照。冷启动和缓存重跑仅在相关路径改变时专项测量。p95 在样本足够且需要评估尾延迟时使用，小样本不设 p95 验收门槛。出现明显成本增长时保留实验状态，说明质量收益及取舍后再决定默认启用。

### 最小评测入口与证据

先用一个最小命令行入口调用生产模块，接受样本清单，保存识别输出与评分差异；不先建设独立评测包、配置框架或可视化平台。已有 `Tools/ScenarioEvaluation` 继续只评版式归属，不用模板分数代替字段准确率。重复运行确实需要统一管理时，再整理工具结构。真实 Provider 评测另行明确样本出网范围和调用预算，本次文档修订不执行该步骤。

每次实际运行保存输入摘要、源码与配置、原始结果、评分差异、请求数和耗时。覆盖叠图只保存首轮代表样本、几何变更样本及失败页；详细内存与性能日志按触发条件生成。复用同一份只读输入清单，输出使用新目录，保留失败证据，不覆盖原稿或正式库，不记录密钥，不将真实样本提交仓库。

## 十 风险与回退

| 风险 | 防护与回退 |
| --- | --- |
| 表头识别错误导致裁错区域 | 几何与语义共同检查；全页始终保留；布局不足时使用兼容裁图 |
| 合并范围错误沿多行传播 | 先诊断再辅助，未知保持未知；首版不自动替换继承规则；发现严重误关联即关闭结构提示 |
| 主识别与查漏受同一错误结构影响 | 不向查漏输入主识别答案或继承结果；保留独立全页盘点及区域外覆盖检查 |
| 无损输入导致内存或请求过大 | 本地和传输格式分离、有界解码、按完整请求测量；超限回退 JPEG |
| 新裁图与历史任务无法对应 | 映射缺失就走旧视图；不推断拼接位置，不迁移历史图片 |
| 复核目标定位错误或过于分散 | 无法可靠覆盖时回退全页及原视图，不增加无界调用 |
| 截断输出被误当完整表格 | 保留当前截断失败及主备机制，不采用保留截断识别文本的路径 |
