## 现在的执行与报告语义

1. 准入、来源、资源、工具、测试范围及脚本自检先执行；失败时不继续运行依赖它们的构建/GUI 步骤。
2. 核心测试、Debug UI 和 Release 归档/交付 UI 仍有各自的执行证据；同一 UI 场景在两条 lane 失败仍分别记录。
3. 聚合契约和覆盖检查缺少已通过的上游输入时标为 NOT_RUN，并保留具体依赖状态。NOT_RUN 不是 PASS，也不会把整体失败改为成功。
4. 正式结论前复核审查提交。诊断脏工作区不授予批准；functional 模式仍不授予发布批准；完整发布仍要求原性能预算与 Owner 批准。
5. 中途取消留下明确未完成的快照。完整日志、原始 xcresult、失败截图和 AX 文本仍保留，简短摘要不能代替原始证据。

## 滚动 FPS 的代码路径修复

- 现有报告空闲约 59.24 FPS、滚动约 31.64 FPS，支持重点检查带滚动负载的路径，但没有调用栈可量化各函数占比。没有将失败简单归为 runner，也没有宣称已证明唯一瓶颈。
- `EditableCSVTableRepresentable.Coordinator.tableView(_:viewFor:row:)` 原来每次都桥接/搜索列数组、生成复用标识、设置编辑性/对齐/文本，并立即格式化行列 AX 标签。现在列重建时准备稳定的源列绑定，滚动按列对象身份直接查找；相同属性不重复写入。
- 单元格仍是原生 NSTextField，保持原文本布局、field editor、输入法和多行粘贴行为。仅通过小型子类在 AX 客户端实际读取标签时格式化；缓存只属于单个复用单元格，行/表头/语言变化后更新，不缓存整个 10k 表的标签。
- 同时修复原先按显示位置取数据的列重排问题：源列索引用于显示和提交，键盘移动另行映射到当前显示位置。列宽采样、手动列宽、固定行高和原生复用机制保持原契约。
- 性能报告新增绑定/创建/文本写入/样式写入/AX 格式化计数，耗时边界外读取计数。120 次首尾跳转、10 ms 间隔、显式 needsDisplay、45 FPS 断言及其他预算未修改。
- 补充标签惰性读取、重绑定与语言变化、列重排后显示/提交身份的回归断言，未运行。本轮仅做静态代码/SDK 契约审查与语法解析，不提供新的 FPS 数值。
- Swift parse-only 与 `git diff --check` 通过。静态 UI 审计仍返回原有 69 条 HTML 文档/原型问题，与此前报告逐条一致；该审计未通过，不涉及本轮原生表格变更。
