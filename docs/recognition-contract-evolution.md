# 场记识别实现演进决定

日期：2026-10-27。依据：用户要求继续完成本地识别优化方案。

本次实施允许调整 SM-05／SM-06 中直接阻碍该方案的实现冻结，采用以下版本边界。旧夹具和历史批准仍保持原样；新流程用独立回归验收，不以改变旧期望值代替验证。

## 模板与观察

- Scenario Profile 的存储 envelope 和项目包仍为 v1；增加可选 structure 描述，结构提取和新模板指纹版本为 2。旧 Profile 缺少 structure 时仍可读取，旧指纹计算及 v1 差分测试继续保留。
- 正式模板使用原有稳定 ID。用户把新观察关联到已有模板时，仅为缺少描述的旧版式补充结构，保留已有可靠结构、名称、旧身份、字段配置、提示和 Resolve 配置。
- 匹配快照同时读取模板及已人工确认的候选／歧义观察，将关联结构作为同一模板的匹配备选；原模板结构不被覆盖。精确人工关联优先于普通结构推断，冲突的人工关联仍返回歧义；自动复用观察不扩展规则。关联按当前别名解析，合并／撤销即时生效，已有确认记录无需迁移即可使用。
- 自动识别改用逐页只读匹配，输出已复用、新候选、候选接近、证据不足。新结构不会自动创建正式模板；当前可靠表头可辅助本页识别。
- 候选使用既有 scenario_observations 的可空 profile_id，fingerprint_version=2 标记观察格式；最多保留 100 条未关联的观察。旧版观察和已关联证据不参与这项清理。
- 成功识别及任务保存之后才记录辅助观察。精确输入摘要确定观察身份，重复执行不增加独立样本计数；未关联观察可以在后续确认匹配时关联正式模板。
- 模板确认通过 ProjectRuntime 租约和 SQLite 事务提交；评测器没有持久化依赖，不更新模板、计数或 lastUsedAt。
- 历史重复模板通过预览后的显式合并保留为别名；旧 ID 仍可读取，历史任务与观察不重写。合并与撤销比较实际配置，前后 JSON 持久保存，未知字段保留。
- 新版特征、候选交互不承诺被旧 Electron 版本理解；旧 v1 数据、原项目表结构和任务结果保持可读。安装旧版本前仍需使用独立备份，不将旧客户端缺少新功能称为数据迁移完成。

## 图像与 OCR

- 本地 OCR 先使用保留的高质量页面，Provider 压缩仅作用于传输图片；归一化坐标继续对应同一页面／视图内容。
- 主识别与核心查漏分别生成 OCR 证据，逐页模板提示进入阶段请求和恢复缓存键；不同版式的页不共享同一模板提示。
- 查漏和裁决保留同页全页参照，防止固定局部图遗漏右侧机位；高精度模式可能因此增加图像输入量。每次实际请求连同 schema、证据、模板与裁决目标一起测量大小，编码结果直接用于发送；格式降级重新测量。
- 生产运行时复用 OCR 引擎与 Paddle worker，每次任务仍拥有独立 MediaOCRWorkflow、取消令牌和进度。关闭任务不关闭共享引擎，运行时退出／配置重置排空所有任务后关闭资源。
- 缓存按项目和视图精确内容隔离，未命中视图合并到一个有界引擎请求，维持一次租约及正常超时策略。64 个视图覆盖现有 20 页 × 3 视图的上限；兼容构造路径仍保留 8 项文档缓存。
- 缓存键保留有效 OCR 配置、尺寸、顺序与内容摘要，避免将完整图像再次 Base64 编码以计算键。项目关闭／取消只清除对应缓存，不取消其他项目的 OCR。
- Paddle 空闲 5 分钟后使用同一排队租约释放 worker，新工作会撤销过期回收；正常关闭取消空闲任务并排空。标准模式的直接准备路径只生成全页，预览已有页面继续复用。
