# SM-03 — Domain, settings, logs and credentials

## Objective

Port the frozen shared contracts and their compatibility rules into typed
`SlateSyncDomain` values, preserve the Electron configuration/data-root
semantics, add structured redacted logging, and migrate legacy provider keys to
the real macOS Keychain transactionally. The native app receives only the
minimum startup bootstrap and a secret-free status snapshot; the complete
Provider/OCR editing workflow remains an SM-08 concern.

## Implementation boundary

- Keep `Codable + Hashable + Sendable` wire contracts and strict discriminated
  unions. Use `JSONValue` only at tolerant legacy/diagnostic boundaries.
- Decode old task snapshots with missing optional fields, including
  `PersistedRecognitionSheet.warnings`, and preserve `providerId` through
  `UpdateCustomProviderRequest` Codable round-trips.
- Separate strict `WorkflowConfig` validation from forgiving persisted
  `ProjectSettings` normalization. Match JavaScript for trimming, casing,
  numeric parsing/formatting, UTF-16 lengths, `.env` CRLF/LF parsing, Provider
  IDs, URL authority/port/path encoding, and dynamic PaddleX cache defaults.
- Keep one `GlobalSettingsResolution` precedence implementation and expose
  value sources through the persistence adapter. The precedence is explicit,
  global config, legacy OCR Python path, process environment (including its
  empty-value mask), `.env`, then defaults.
- Keep non-secret configuration recoverable when permissions cannot be
  tightened. Treat the legacy credential file as fail-closed: do not read or
  delete it when its protection cannot be established.
- Use a stable Application Support lock namespace with a bounded wait; Keychain
  production calls use the Data Protection Keychain and `AfterFirstUnlock`.
  Conditional compensation matches both value and ownership marker. Preserve
  cancellation semantics and numeric OSStatus diagnostics without secrets.
- Bound recursive JSON/log scans, redact at field boundaries and credential
  patterns (including Google `AIza...`), and keep ordinary fields such as
  `author` public.
- Wire `SlateSyncRuntime` into `SlateSyncApp` and expose only migration/config
  status in `SettingsRootView`. Migration failures are retryable, secret-free,
  and must not prevent the App from opening.
- Gate diagnostics classify real assertions/crashes before marker or
  environment text and never treat arbitrary passing summary prose as failure.

## Verification and governance

The implementation package is ready for formal review when SwiftPM build/test,
Xcode Debug/Test Plan, Node compatibility/typecheck/modern build/native ABI
checks, phase-gate fixtures, `sm03_contract.mjs`, and `git diff --check` pass.
The dirty `./script/phase_gate.sh SM-03 --allow-dirty` run is diagnostic only;
formal completion continues through a dedicated review commit, a clean Gate,
an evidence report, and explicit Repository Owner approval before updating
`CURRENT_STATE.json`.
