### WP-2 — 原生文件解码、PDF 渲染与资源所有权

1. 文件入口先检查类型、字节上限、可读普通文件，再按实际内容解码；扩展名/MIME
   只作提示，不能让伪装 PDF 或损坏图像通过。关闭读取或复制过程中大小变化的漏洞。
2. ImageIO 读取尺寸与方向，按目标尺寸解码而非先无界展开大图；处理 EXIF 旋转、
   alpha 白底和首帧规则，不额外扩展 GIF/HEIC 等产品输入种类。
3. PDFKit 校验空页/锁定/页数/有效有限 bounds；对 crop box、media box、rotation
   与 pdf.js viewport 做差分后选择等价绘制矩形，不能直接沿用 thumbnail 外观假设。
4. 每次只渲染一页，及时释放 PDFPage/CGContext/CGImage 和中间 buffer；尺寸乘法
   检查溢出，创建失败可诊断。成功前不发布半份文档。
5. 每页、分析批次和编码间检查取消；同步框架调用返回后再次检查 token。取消后的
   结果不进入缓存或下游，即使该框架调用本身不能立即中断。

交付：支持四种输入和 1/20/21 页边界，错误与取消均释放资源。

### WP-5 — Paddle Python 受管进程与生命周期

1. 复用现有 Python runner 和协议：`--check`、`--server`、requestId JSON lines、
   warmup/recognize/shutdown、JSON 与 PROGRESS sentinel；保留 one-shot 入口。
   Swift 通过 Process 的 executableURL/arguments 启动，不拼接 shell 命令。
2. runtime resolver 注入开发根/原生 bundle Resources 根、Python 路径、cwd 与
   模型缓存根。runner 放只读资源目录，可写缓存单独定位；配置相对路径仍有明确
   基准。脱离仓库 cwd 的 bundle fixture 必须可运行，不能依赖 `app.asar`。
3. actor 管理一个串行常驻 worker、pending request、warmup single-flight 与 generation。
   有效配置变化先排空/关闭旧 worker 再启动新 worker；同配置只预热一次。
4. deadline 在进入队列时创建；排队、启动、预热、识别与 one-shot 恢复共享剩余
   时间。排队取消/超时只移除本请求，不杀正在服务其他请求的 worker。
5. 活跃请求取消/超时需终止其 worker，等待退出、关闭 pipes、取消 reader/timer，
   然后完成一次且仅一次。force close/shutdown 推进 generation，旧 preload、迟到
   请求及配置切换 completion 不能复活进程。close 必须可重复且并发调用安全。
6. 常驻协议不支持、启动失败或异常退出可在清理旧 worker 后尝试一次 one-shot；
   取消、deadline 耗尽或主动 shutdown 不得恢复。不能同时遗留两套推理进程。
7. 并行排空 stdout/stderr，支持任意字节拆包、UTF-8 跨块和多行一次到达；缓冲区
   有上限。协议超大帧不可截断成“成功”；缺失/畸形结果、错误 requestId、重复 final、
   EOF 和 broken pipe 均有确定处理，不悬挂 continuation。
8. 使用 `child-environment.mjs` 对应的 macOS 最小环境白名单；运行时不继承
   Provider key 或 `PIP_*`。代理/证书值按既有策略允许但不落日志。测试向 fake child
   注入假 secret 验证隔离；仅管理自己启动的 PID，禁止按 python 进程名批量 kill。

1. 原样移植 selection：Vision required → Paddle required → Vision explicit →
   Paddle explicit → Vision 显式关闭分支 → auto Vision → auto Paddle → disabled。
   用 raw 配置向量和 SM-03 归一化配置分别测试，不能只测 UI 能产生的组合。
2. required 的引擎不可用、异常、`used=false` 或零有效 blocks 均阻断下游；optional
   失败/空结果返回图片可继续的明确 warning；disabled 不启动 OCR。
3. 选择阶段的引擎 fallback 与执行失败区分：不能自行发明 Vision 失败后再跑 Paddle
   的链路。执行失败沿当前 optional/required 策略处理；取消永远是终止。
4. 分别实现 8 项 LRU，成功后才写入。key 使用长度分隔/结构编码，覆盖模型版本、
   preset/profile、det/rec、batch、detSide、language/device、置信与上限；Vision 还
   包含 level/correction。相同 bytes 的 `[A,B]` 与 `[A],[B]` 不得碰撞。
5. cache=false 同时跳过读写；命中提升 LRU 并发出 cache-hit。失败、取消、未完成
   不写缓存；项目会话切换/关闭主动清理或用会话隔离 key，避免跨项目暴露 OCR 文本。
   清理后旧 generation 的完成不能重新填充缓存。
6. 移植 normalize/summary/full-core evidence formatter，保留有效文字、坐标、
   置信、视图尺寸、截断与 omitted 标记；精确验证中英文及 emoji 的 UTF-16 预算。
   不改变 SM-07 的识别 prompt/schema，也不把 OCR 文字直接当最终场镜次记录。

交付：明确的 outcome 状态、零下游调用的取消/required 回归、LRU 与 evidence goldens。

### WP-7 — Workflow 组合与 SM-05/07 交接

1. 新增聚焦的 `MediaOCRWorkflow` façade，组合 prepare → view selection → local OCR
   → evidence/summary；依赖注入下游 spy 验证顺序，不实现网络 transport 或完整
   `RecognitionCoordinator` 的 SM-07 编排。
2. OCR evidence adapter 输出 SM-05 的 `ScenarioObservationInput`，保留页/视图
   尺寸、坐标与引擎标记。用固定 evidence 验证既有 fingerprint 不漂移；本阶段
   不自动学习写库，后续 Scenario 写入仍经 `ProjectRuntime` 租约。
3. SM-05 留下的 legacy take-status 字符串（`_OK`、`_KP`、`过`、`保`、`ng`、
   `x`、`×` 等）归 SM-07 识别/CSV adapter 统一转 `TakeStatus`；SM-06 只保留 OCR
   原始文字。交接必须明列此项，禁止通过修改 SM-05 merger 偷渡映射。
4. operation token 覆盖准备、压缩、OCR 和结果投递；取消/替换/关闭后无迟到 progress、
   cache write 或下游调用。日志仅包含引擎、计数、耗时、错误分类和脱敏操作标识，
   不记录文件绝对路径、Data URL、OCR 全文、prompt 或环境值。

交付：服务级隔离、取消后重试、OCR-first 顺序和 Scenario adapter 回归通过。

## 完成定义、风险与后续交接

SM-06 完成必须同时满足：媒体限制/几何/多视图兼容、真实 Vision 与离线 Paddle 可用、
fake 进程故障矩阵通过、required/optional/cancel 明确、缓存隔离、无原始 PDF 下游、
SM-05/现有产品回归通过、clean Gate 和 Owner 批准齐全。

- **渲染差异：** 框架像素可不同，但标题、表格、局部图与坐标不能丢失。通过固定
  几何、标记区域和审核容差验收，禁止把 JPEG byte hash 当跨引擎内容正确性的唯一证据。
- **原生取消：** actor 不代表同步 Vision/PDF 调用可立即中断；保留 request owner、
  deadline 与 generation，确认工作结束后再报告排空，不能靠丢弃 Swift Task 假装停止。
- **进程竞态：** warmup、配置切换、排队与 close 重入会复活 worker。必须在 fake
  实际进程上覆盖交错时序；mock transport 通过不足以证明没有孤儿进程。
- **输入/模型环境：** WebP 解码能力、显式 Vision helper、Paddle Python/模型兼容性
  需真实环境证据；缺失应记录 BLOCKED_ENV，不能静默移除支持或借用用户 runtime。
- **阶段越界：** SM-07 接收 images/evidence/summary/selection 和取消契约，负责
  Provider 请求、重试/并发/进度编排及 TakeStatus adapter；SM-08 负责原生设置/安装
  交互；SM-09 负责 Universal 分发验证和 Electron 清除。

如需改变产品限制、已保存设置语义、Scenario fingerprint 或 OCR-first，先记录
`DECISION_QUEUE.md` 阻塞并取得兼容决策，不改 golden 规避。回退以本阶段聚焦文件和
专用提交为单位，不触碰用户数据、既有 SQLite/CSV 格式或历史证据。
