# SM-08 — Native product workflows

## 施工目标与文档状态

本施工包在 2026-09-05 细化，用于把已经完成的 Domain、Persistence、Media、
Workflow 与 Provider/Recognition 能力接入完整的原生 macOS 产品工作流：

- 用 SwiftUI scenes、commands、toolbar、source list、sheet、alert、file panel 和
  accessibility API 完成 Project Library、Workspace、Task、Recognition、CSV、

  兼容回归后，生成独立 review commit 与 clean Gate 证据，等待 Owner 批准。

2. 保持五个业务模块：`SlateSyncDomain`、`SlateSyncPersistence`、`SlateSyncMedia`、

8. 修改代码时同步添加或更新非显然的状态所有权、generation、自动保存、取消、

## 原生 UI 架构与状态所有权

### Scene、session 与 feature model

1. `SlateSyncApp` 保持唯一 composition root。`WindowGroup` 承载主产品窗口，`Settings`
   scene 承载全局设置；使用原生 commands/toolbar，不造自定义标题栏或 Web 式侧栏。
2. 每个主窗口拥有一个 `@MainActor @Observable AppSessionModel`，其生命周期高于 route
   view。session 持有当前 project/task selection、workspace operation 引用与导航 guard，
   但不承载 CSV 10k rows、设置全表、日志全表等所有 feature 状态。
3. 每个功能使用聚焦 model：ProjectLibrary、Workspace、TaskRail、Recognition、
   ResolveCSV、GlobalSettings、ProjectSettings、Logs、Help。大型值由 actor/service 持有，
   model 只发布渲染所需快照；禁止 mega-store、隐式全局 mutable singleton 与双份真相。
4. 每次 project/task/provider/model selection 变化都递增 generation。异步 completion
   必须同时匹配 owner identity、generation 与 operation ID 才能更新 UI；迟到结果只清理
   自己拥有的资源，不能覆盖新 selection。
5. `ProjectRuntime` lease、`RecognitionCoordinator` operation、autosave writer、log reader
   和 Paddle installer 都有单一 owner、幂等 close 和可等待 drain。SwiftUI view 消失不等于
   资源已结束，禁止依赖 `deinit` 或未结构化 detached task 做清理。

### 导航与 lifecycle 转移矩阵

| 事件 | 必须先做 | 成功后 | 失败/取消后 |
| --- | --- | --- | --- |
| 切换 sidebar route | 若离开 active editor，flush autosave | 更新 route；recognition 可继续 | 保持原 route 与焦点，展示可重试错误 |
| 打开另一项目 | flush task/cell，结束旧 project-scoped transient work | close 旧 runtime，再 acquire 新 runtime | 保持旧项目；不得出现双 runtime |
| 切换 task | flush 当前 task/cell | 更新 generation 并加载新 task | 当前 task 保持选中 |
| archive/change/import/rename Library | 使用同一 workspace barrier | 操作后刷新并恢复稳定 selection | 原上下文不丢失；给出下一步 |
| 删除项目 | exact-name 二次确认、flush、cancel/drain、close lease | 调用 SM-04 delete，选择下一个合法 route | 项目仍可操作或明确 tombstone 状态 |
| 窗口关闭 | 提交局部 edit；按 policy flush；取消 window-only reads | 释放该 window models；App 可继续运行 | 系统关闭请求被取消并聚焦错误 |
| App terminate | 通过 AppKit delegate 发起 async drain | 所有 writer/operation/process 完成后 reply terminate | reply cancel，窗口恢复并显示阻断原因 |
| reopen/activate | 无主窗口时请求 SwiftUI 新窗口 | session 从持久化选择/默认 route 初始化 | 启动错误进入可恢复 degraded state |

AppKit lifecycle 逃生口只允许一个窄的 `NSApplicationDelegate` adapter，用于
`applicationShouldTerminate` 的异步 drain/reply 与必要的 reopen 协调；业务逻辑仍在
Swift actor/model 中。macOS 关闭最后一个窗口不等于退出进程，测试必须覆盖 close、reopen、
⌘Q、系统 terminate request 和失败重试，而不是仅验证 view disappear。

### 唯一允许的 AppKit bridge

1. `EditableCSVTableRepresentable` 包装 `NSScrollView` + view-based `NSTableView`。
   Coordinator 负责 stable row identity、column width、selection、edit session、scroll
   position、accessibility 与 Swift 回调；Coordinator 不拥有业务真相或写数据库。
2. 文件/目录选择优先 SwiftUI `fileImporter` / `fileExporter`；只有目录权限、UTType 或
   save panel 行为不足时，才以聚焦 adapter 使用 `NSOpenPanel` / `NSSavePanel`。
3. termination/reopen 使用上述 App delegate adapter。除此之外，不以 `NSHostingView`、
   responder-chain hack、私有 API 或自绘窗口替代 SwiftUI scenes/commands。
4. bridge delegate 回调立即转成 Sendable 值并回到 `@MainActor` model；不得从 background
   callback 直接改 observable state。teardown 必须移除 observer、timer、data source 与
   pending edit，并由资源测试证明。

### WP-2 — Project Library 与 Project Settings 完整工作流

1. 使用原生 source-list/table 稳定显示 Active 与 Archived；支持 refresh、create、open、
   settings、archive、restore。loading/empty/error 不改变主布局，selection 使用 project ID。
2. create sheet 含可见 label、名称校验、可选 description；提交中防重复，成功后打开项目，
   失败保留输入与第一处错误焦点。⌘N 与按钮调用同一 action。
3. Project Settings 编辑 name、description 和 project-scoped recognition/CSV/Scenario；
   save 使用 immutable draft + validation + atomic service call，不写入全局 Keychain/provider。
4. archive/restore 可恢复；archive 当前项目先经过 workspace barrier，成功后回 Library。
   Archived 项目不能进 Workspace，只能 settings 或 restore。
5. project/library import/export/change-library/rename-library 复用同一 file-panel adapter、路径/
   extension 验证、workspace barrier 与 SM-04 service。cancel 无副作用，错误保留 session。
6. project delete 使用两阶段 destructive confirmation，要求逐字输入当前 project name。
   IME composition 期间 Enter 不提交；delete 顺序为 flush → cancel/drain → close runtime →
   SM-04 tombstone delete。
7. operation 都有 idle/running/succeeded/failed/canceled；destructive action single-flight，
   selection/window 改变后旧 completion 不得写入新项目。
8. 500-project fixture 验证首次加载、稳定 selection、滚动、archive/restore 与内存；不得为

交付：Project Library/Settings unit、integration、UI、accessibility 与 scale tests 通过。

### WP-3 — Workspace、Task rail、输入、预览与单一自动保存

1. Workspace 使用原生 split view：左侧 task rail，中部输入/识别/结果，必要时使用 inspector。
   窄窗口可压缩，不把 CSV 放进外层纵向 scroll。
2. Task rail 支持 list/refresh/create/select/delete、stable ID、状态标签和兼容搜索/clear。
   1,000-task fixture 必须 lazy/reuse，selection 不因 refresh/sort/completion 漂移。
3. 新 task 的 Main/文件名/默认值由 Workflow/Persistence façade 决定；UI 不自行生成与旧
   schema 冲突的 ID。删除前结束 transient work、flush/close editor，再调用 runtime。
4. slate PDF/image、可选 slate CSV、Resolve CSV 与 metadata directory 的 button/menu/drop
   全走同一 validation/action。drop 有键盘替代；security-scoped URL 明确成对结束。
5. preview 支持 PDF/image 缩略与 lightbox、上一/下一页、左右键和兼容水平触控板 burst；
   文本编辑焦点下不劫持方向键。解码只走 SM-06 façade，迟到页不覆盖新文件。
6. 建立唯一 project/task-scoped autosave actor：500 ms debounce、serialized write、最新
   immutable snapshot、generation、`flush()`、`retry()`、`reset()`；禁止 view 自建 writer。
7. flush 失败保持 task/project/route 与 draft，显示脱敏 retry/cancel guidance；不得清除 dirty
   state、吞错或让旧 write 覆盖新更新。
8. App close、project/task/route switch、archive/import/change/delete 和开始 recognition 都用
   同一 barrier；覆盖并发 edit/switch、write failure、late completion、teardown/close 竞态。

交付：完整 Workspace shell、输入/预览与 autosave deterministic tests 通过。

### WP-4 — Recognition 控件、进度、取消与结果编辑

1. UI 从 SM-07 façade 读取 Provider/model availability、Scenario/custom prompt、accuracy 和
   Slate CSV context；不得重建 registry、filter、prompt、request budget、OCR 或 limiter。
2. Recognize 前 flush 当前 draft 并 validation；显示 provider/model、standard/high、Scenario
   与上下文摘要。不可用/未验证模型提供设置入口，不能 optimistic 绕过。
3. progress 展示 SM-07 stage、page/total、percent、可取消状态和脱敏 message；切到 Logs/
   Settings 后 operation 不卸载，返回 Workspace 可重连 snapshot/stream。
4. Cancel 调用 project-scoped cancel 并等待 drain；canceling 状态和重复 cancel 幂等；完成/
   取消竞态仅一个 terminal state，无无主 network/OCR/persistence task。
5. 成功结果经 Domain/Workflow 值显示；250 ms queued edit 使用 stable row/material ID，
   blur/Enter 提交，Escape 只撤销 local draft，IME composition Enter 不提交。
6. 本地 slate CSV merge 调用 SM-05 merger，与远端 recognition 共用结果 model/autosave，
   不复制 TakeStatus、Comments 或 CSV 合并语义。
7. supersede、task/project switch、termination、global 429、Provider/OCR/页/持久化失败均有
   固定恢复路径；错误/日志/诊断/UI 只展示 whitelist 字段。
8. 注入回显 Authorization/key/provider body，证明 UI、accessibility tree、snapshot 和 log
   file 都无泄漏。

交付：recognition lifecycle、progress、cancel、result edit 与 secret-negative tests 通过。

   width 单一真相；SwiftUI update 后保持 scroll、selection 与 edit draft。
3. 10,000 行全部可编辑；250 ms commit、blur/Enter/Escape、Tab/Shift-Tab、方向键、Home/End、
   copy/paste 按冻结矩阵执行。IME marked text 期间不得提交、撤销、切行或触发快捷键。
4. Coordinator 只上报 `(tableID,rowID,columnID,revision,value)`；MainActor model 检查
   generation/revision 后交给唯一 writer，cell 不直接写文件/数据库。
5. VoiceOver 可读 table、row/column header、cell、错误与 editable state；keyboard-only 可从
   toolbar 进入、编辑、离开并到 Export，颜色不是唯一状态表达。
6. metadata scan 走 SM-05 service；progress/empty/error、cancel、权限拒绝、目录变化与迟到
   completion 由 operation generation 隔离。
7. preview/export 共用 canonical encoded bytes；save panel cancel 无副作用，成功只报告文件名/
   行数，失败不宣称 partial file 成功。
8. 性能记录首次 snapshot、末行滚动、键盘响应、cadence、visible views、峰值内存和退出释放；
   检测 hidden duplicate、retain cycle、timer/observer 泄漏。

交付：SM-05 字节差分、10k grid 功能/IME/A11y/性能和资源释放验证通过。

### WP-6 — 全局/项目设置、Provider、Vision 与 Paddle 管理

1. Global Settings 按 General、Providers、Recognition、OCR、Storage/Advanced 分组。外观/
   density 是 UI preference；业务配置使用 typed `GlobalSettingKey`，不直接绑定字典。
2. draft/load/save 区分 persisted、editing、saving、saved、failed；成功后才更新 live snapshot。
   validation 有 label + inline error，首错可聚焦/朗读，失败 draft 不因换 tab/window 丢失。
3. 内建 Keychain key 只显示 configured/missing，支持 save/replace/clear，永不回显现值；secure
   field、undo、pasteboard、accessibility、错误和日志都不得包含 key。
4. Custom Provider 支持 CRUD、Base URL/model/transport/json/detail、optional key、revision 与
   destructive confirmation；discovery/manual model/probe/cancel 全调用 SM-07 façade。
   原生 `Picker`/table 是 canonical control，不移植 custom web listbox。
5. late revision 不回填；编辑/删除 Provider 时 cancel + drain；失败 message 脱敏并保留
   retry/manual path。
6. OCR preference 支持 auto/vision/paddle/disabled、presets、Vision availability/check 与
   Paddle config/check，调用 SM-06 façade。
7. Paddle installer 安装到受管 `paddleocr-venv/bin/python`，固定
   `paddlepaddle==3.3.1`、`paddleocr==3.7.0`；要求 Python 3.10+；stages 固定为
   detect-python 5%、create-environment 20%、install-dependencies 35%、verify 90%、
   completed 100%；命令 timeout 30 分钟、single-flight、cancel 后 TERM → 2 秒 → KILL。
8. installer 只运行 bundle 固定 requirements/脚本，sanitized environment，拒绝 symlink/path
   escape；自动测试注入 process/clock/filesystem 且绝不联网。真实安装缺环境记
   `BLOCKED_ENV`，不得伪装自动 PASS。
9. Project Settings 只保存 project-scoped context；Library path change/rename 调用 SM-04 API
   并经过 workspace barrier/restart-required flow。

交付：settings、Keychain、provider/discovery/probe、OCR checks 与 installer tests 通过。

### WP-7 — 本地日志、Help 与恢复反馈

1. Persistence 建立 actor-owned local log store/sink，同时保留 `OSLog`。受管 logs 目录中使用
   `slatesync-YYYY-MM-DD.log`；目录 0700、文件 0600、保留 7 天、serialized advisory writes。
   日志失败不得中断产品流程。
2. typed log projection 只记录时间、severity、category、event、允许的 progress IDs/数字与
   脱敏 message；禁止完整 request/response、prompt、CSV、媒体路径、Authorization、key、
   原始 Provider body。
3. reader newest-first，默认 500、clamp 2,000；severity/category filter、3 秒 polling。
   rotation/partial last line/malformed line/permission error 进入 degraded，不因坏行清空全部。
4. Logs 同时显示当前 recognition 摘要与本地 entries；route 不拥有 operation。Open Logs Folder
   使用系统 Workspace/open URL adapter，UI/日志不展示完整内部路径。
5. Help 使用 6 个 bundle-local sections、目录与本地搜索；无 WebView、remote content、
   analytics 或网络依赖。验收覆盖中文、空查询、no-result、键盘定位与 VoiceOver；不要求其他语言专项覆盖。
6. WP-0 冻结 help content SHA；settings/provider/Paddle 名称或步骤变化时同步正文、快照和 SHA。
7. error/degraded view 保持稳定布局，说明发生事项、数据安全和下一步，并提供 retry/open
   settings/open logs；展开的技术详情也必须脱敏。

交付：文件日志权限/保留/恢复/脱敏测试、Logs UI 与离线 Help tests 通过。

### WP-8 — Accessibility、IME、multi-window、lifecycle、性能与视觉收敛

1. 全产品 audit 中文 label/value/hint、heading/group/table semantics、focus order、keyboard-only、
   VoiceOver、状态 announcement、错误关联、等效命中区、contrast、Increase Contrast、Reduce
   Transparency、Reduce Motion 与大字号。
2. TextField/TextEditor/NSTextField/NSTableView 覆盖中文拼音 IME marked text、Enter/
   Escape/Tab、debounce、切换/关闭与 validation；composition 时不得 destructive submit。
3. 测试两个主窗口的不同项目、同项目冲突 policy、单窗关闭、另窗继续、Settings 独立打开、
   最后窗口关闭后 reopen；共享/隔离由明确 policy 决定。
4. 覆盖 ⌘Q、Dock quit、系统 terminate、flush/installer/recognition cancel failure、重复 terminate
   与 deadline；证明 reply 一次、无僵尸 URLSession/Process/SQLite owner。
5. 在 960×600、1440×900 与更大窗口检查 split/toolbar/sheet/settings/log/help/grid，无主操作
   截断、nested scroll trap、布局跳动或不可达错误。
6. 运行 500-project、1,000-task、10k-grid 与 recognition teardown；记录机器/build/config、
   5 次样本统计、threshold 与原始结果。性能失败不得以“看起来顺畅”通过。
7. native visual review 验证 system control、spacing、typography、semantic color、dark/light/
   high-contrast 与 dense hierarchy。截图是忽略的 Gate evidence，只提交 concise review。

交付：A11y/IME/multi-window/lifecycle/performance/visual review 全部 PASS 或明确 BLOCKED_ENV。

### WP-9 — SM-08 Gate、独立审查与治理收尾

1. 扩展 `script/phase_gate.sh SM-08` 与 self-tests：准入、模块依赖、AppKit bridge allowlist、
   fixture hashes、coverage、SwiftPM、Xcode Unit/UI、Debug/Release/Archive、隔离启动、A11y/
   IME/lifecycle/性能/资源与 secret-negative evidence。
2. 本阶段仍运行 Electron/Node/Modern compatibility matrix，证明 native UI 接入未改坏 CSV/
   data/provider/media contract；Gate 不删除或修改旧 oracle。
3. 原始证据写入忽略的 `.codex/gate-results/SM-08/<run-id>/`，包括 manifest、工具版本、
   xcresult、性能 JSON、视觉索引、bundle/resource audit 与失败分类；仓库只提交长期摘要。
4. 先运行 dirty diagnostic，其结果一律 `approvable=false`。修复结束且用户另行授权后创建
   dedicated review commit，并在该精确 SHA、干净工作树运行正式 Gate。
5. 任一断言失败、证据缺失、SHA 不一致、默认 Library 访问、真实网络依赖、secret 泄漏或
   performance threshold 失败都 fail-closed。
6. 独立审查聚焦 state owner、autosave ordering、AppKit teardown、recognition drain、Keychain/
   log redaction、IME/A11y、data compatibility 与 Gate 完整性，写入 `reviews/SM-08.md`。
7. 只有 clean Gate PASS、review 无阻断且 Owner 明确批准后，治理提交才能把 SM-08 置为
   `COMPLETE` 并开放 SM-09。

交付：精确 SHA clean Gate、review report、Owner approval 与合法状态转移。

## 施工顺序与停止点

```text
SM-07 COMPLETE + 单独授权
  → WP-0 行为/fixture/预算冻结
  → WP-1 composition/session/lifecycle
  → WP-2 Project Library/Settings
  → WP-3 Workspace/Task/autosave
  → WP-4 Recognition/result
  → WP-5 Resolve CSV/metadata/AppKit grid
  → WP-6 Global Settings/provider/OCR installer
  → WP-7 Logs/Help
  → WP-8 A11y/IME/window/perf/visual
  → WP-9 diagnostic → review commit → clean Gate → review → Owner
```

停止条件：

- WP-0 无独立 oracle、兼容源 hash 或预冻性能预算，不得写产品实现。
- façade 需要修改 SM-04～SM-07 兼容契约时，先走兼容决策；不得在 view 绕过。
- autosave/selection/lifecycle owner 不唯一，或 cancel/close 无法 await drain，不得继续。
- 10k table 的 commit/reuse/IME/A11y/释放任一失败，不得用小 fixture 代替。
- 自动化接触默认数据、真实 Keychain/Provider、网络安装或生产日志，立即阻断 Gate。
- SM-08 未 `COMPLETE` 前禁止删除 Electron/Node 输入或启用 release cutover。

## 完成定义、风险与 SM-09 交接

SM-08 只有在所有验收 ID 有证据、SwiftPM/Xcode/兼容 matrix/隔离启动/secret/A11y/IME/
lifecycle/multi-window/performance/resource tests 全部通过、AppKit 仅使用 allowlist bridge、数据与
业务契约无漂移，并完成精确 SHA clean Gate、独立 review 与 Owner 批准时才算完成。

主要风险是把 SwiftUI view 生命周期误当业务生命周期、多个 writer 覆盖、AppKit retain cycle、
IME/快捷键冲突、隐藏 eager rendering、late completion 污染新 selection，以及 Keychain/provider
message 经日志或 accessibility 泄漏。必须用 owner、generation、deterministic tests 和资源测量
关闭，不能仅靠人工“界面可用”。

交给 SM-09 的唯一前置是：完整原生工作流已经在保留 Electron/Node oracle 的条件下正式通过。
SM-08 不删除兼容源、不切 CI/release、不改变签名策略；SM-09 从已批准的 SM-08 commit 开始做
最后兼容矩阵、原生打包和 production-input cutover。
